# 17차 — 공통 아이돌 프로필·통합 선수 분석

## 사전 분석과 데이터 보호

개발 전 실제 세이브는 DB 11, `absolute_day=14`, 정규 완료 55경기였습니다. SQLite 온라인 백업을 `data/backups/idol_manager_before_profile_development_20261028_094533_201216_KST.sqlite3`에 만들었고, 별도 복사본과 임시 게임에서 시험했습니다. DB 버전은 **11 그대로**이며 새 테이블·마이그레이션·가짜 계약 데이터는 추가하지 않았습니다.

마스터 기획서의 프로필·부상·등록·경기·성장 규칙과 17차 요청을 확인했습니다. 실제 저장 구조는 다음과 같습니다.

| 정보 | 기존 저장·처리 |
|---|---|
| ID·이름·사진·나이·건강·현재 능력치 | `people`, `idols`, `abilities.value` |
| 현재 기획사·신분·리더 | `roster_memberships`, `squad_leaders` |
| 과거 프로 공개 이력·최초 지명 | `professional_history`, `draft_picks`, `draft_turns` |
| 13차 추정치 | 변경 금지 트리거가 있는 `draft_estimates` |
| 실제 출전 날짜·피로·등록·부상·휴식 | `appearance_days`, `player_conditions`, `condition_events`, 기존 `public_condition()` |
| 정규 경기 | `match_player_stats`, `match_events`, 기존 일정·참가 기획사 |
| 특별전 | `special_player_stats`, `special_judgments`, `special_rounds`, `special_team_results` |
| 결정전·포스트시즌 | `final_contests`의 완료된 결과와 저장 이벤트 |
| 성장·노화 | `development_days`, `development_results`, `development_settlements`, 공개 변화만 추출한 `development_trials` |
| 사진 | 기존 비동기 `ThumbnailCache`, 프로필용 고해상도 캐시 |
| 계약·급여·이적·이후 시즌 신규 드래프트 | 실제 계약 엔진·저장 테이블·전용 목록은 아직 없음 |

프로필을 위한 별도 선수 데이터 복제본을 저장하지 않습니다. `ProfileService`는 읽기 트랜잭션 안에서 `PRAGMA query_only=ON`을 설정합니다. 조회 과정에는 난수 사용·날짜 진행·성장 실행·지명 호출이 없습니다.

## 공통 프로필과 열람 위치

`ProfileDialog`는 한 명 조회와 두 명 비교에 같은 `ProfilePanel`을 사용합니다. **개요 / 능력치 / 컨디션·부상 / 경기 기록 / 계약·이적 / 성장 기록**의 6개 탭입니다. 사진 비율 유지, 누락 사진 플레이스홀더, 숫자·막대그래프, 한글 안내, 스크롤, 표 열 너비 저장을 사용합니다. 작은 창에서는 내용에 스크롤을 적용합니다.

이름·사진의 단일 클릭을 아래 위치에서 연결했습니다.

- 기존 아이돌 명단의 우리/다른 기획사 선수, 1군·2군·연습생
- 기존 드래프트 후보의 사진·이름, 지명 이력의 이름
- 선수단 관리의 이름·사진 — 최초 편성 체크박스와 별개
- 정규·포스트시즌 출전자, 관전 상세 표, 결과 개인·능력치 기록
- 정규·포스트시즌 사진 대결 카드의 이름·사진
- 특별전 출전자와 결과 개인·능력치 기록
- 성장·노화 명단의 이름·사진
- 새 통합 탐색 화면의 이름·사진, FA 및 미지명 후보 필터 결과

모든 연결은 실제 `idol_id/person_id` 또는 정렬 프록시의 원본 행 ID를 사용합니다. 표 결과의 ID는 정렬 전에 셀 데이터로 함께 넣습니다. 이름으로 역검색하지 않습니다. 후보를 클릭하는 것은 조회이며 지명을 확정하지 않습니다. 창을 닫아도 원래 목록·스크롤·선택을 다시 생성하지 않습니다.

이후 시즌 신규 드래프트·독립 FA 협상·전역 부상 목록 화면은 아직 없으므로 만들지 않았습니다. 해당 화면은 이후 같은 `ProfileController.open(id)`를 호출하면 됩니다.

## 정보 공개 규칙

현재 기획사 소속, 과거 프로 이력, 지명 이력, 저장된 소속·실제 출전 이력으로 공개 여부를 판별합니다. 이미 지명된 선수와 과거 프로였던 FA는 정확한 현재 8개 능력치·건강을 계속 표시합니다. CA는 저장 평균을 그대로 믿는 대신 **현재 8개 값의 산술평균**으로 계산합니다.

지명·공개 이력이 없는 후보는 `draft_estimates.low/high`만 읽습니다. 후보 조회 SQL에서는 실제 능력치·건강·기존 정확한 평균을 읽지 않습니다. 기존 드래프트와 같은 고정 5칸 범위이며, 범위 중앙값만 그래프와 정렬에 사용합니다. 추정 CA도 8개 범위의 평균 하한~평균 상한으로 표시합니다. 범위가 없는 미공개 인물에는 `미공개`를 표시하고 새 범위를 생성하지 않습니다. 미등장 인물은 통합 검색에 추가하지 않습니다.

PA·평균 PA·유망주 내부 표식·성장 상한 잔여량은 프로필 서비스의 조회 항목이나 반환 데이터에 없습니다. 성장 이력에서는 실제 적용된 **0이 아닌 증감**과 원인만 추출합니다. 판정 확률·난수·상한 때문에 적용되지 않은 시도 등은 전달하지 않습니다. 후보 프로필과 혼합 비교에서도 비공개 실제값을 기준으로 정렬하거나 분석하지 않습니다.

## 컨디션·등록·부상

실제 출전 연속 일수와 1군 등록 주차를 별도로 표시합니다. 실제 날짜는 `appearance_days`의 날짜 고유키를 사용하므로 같은 날 두 경기를 뛰어도 하루입니다.

- 현재 실제 연속 기록과 피로: 기존 `public_condition()` 및 `fatigue_penalty()` 사용
- 오늘 다음 경기 출전 시 예상: 기존 판정의 `projected_days`, `penalty`
- 1군 등록 위험: 기존 등록 주차와 `registration_multiplier()` — 3주 10배, 4주 20배
- 선택 시즌 등록 주차: 확인된 일별 소속과 실제 저장 이동을 통해 계산하며, 과거 미확인 구간은 만들지 않음
- 실제 출전 주차: 실제 출전 날짜에서 계산
- 2군 완전 휴식: 저장 완료 휴식 주차와 공통 `required_rest_weeks()` 사용. 기존 서비스의 1/2주 분기를 같은 함수로 추출했으며 값은 바꾸지 않음
- 부상 확률: 기존 `injury_probability(health, weeks, kind)` 사용. 실제 경기·1군 미출전일·2군 소속일의 조건별 확률을 구분
- 부상 날짜·저장 회복 가능일·복귀 제한일: 기존 상태와 발생한 부상 이벤트만 표시

조건에 맞지 않는 소속이나 이미 부상 중인 경우 확률 표시를 실제 추가 판정으로 오해하지 않도록 안내합니다. 건강을 감소시키거나 선수 상태를 복구하지 않습니다. 등록 이력은 현재 위험 계산에 사용되는 단계이며, 휴식으로 초기화되기 전의 누적 단계가 유지될 수 있습니다.

## 경기·성장·계약 기록

경기 통계는 저장된 실제 선수별 이벤트를 집계합니다. 일반 주요/보조, 리더 추가, 데스매치를 분리하며, 실제 경기 횟수·날짜·콘텐츠·상대·결과·경기 후 해당 부상 이벤트를 표시합니다. 당시 능력치를 재판정하지 않습니다.

정규·특별전·포스트시즌·동률 결정전을 필터로 구분합니다. 특별전의 순위 결과는 임의의 승패로 환산하지 않습니다. 전체 성공률은 일반+리더 기준임을 표시하고 DM은 별도입니다. 성장 집계 일반 시도에는 실제 1군의 정규·특별전·포스트시즌만 포함합니다. 2군 특별전 출전, 동률 결정전, 리더·DM은 성장 시도에 넣지 않습니다. 실제 월요일 기본 성장 적용 여부는 그 주의 소속 유형과 부상·피로 등에 의해 달라진다는 안내를 표시합니다.

**성장 정산 반영 시도 / 성장 미정산 시도**를 별도 열로 표시합니다. 저장된 해당 주 정산의 적용 신분이 1군일 때만 확정 반영에 넣고, 적용 신분이 2군·연습생인 주의 1군 출전은 제외합니다. 아직 정산되지 않았거나 도입 전 정산을 확인할 수 없는 기록은 미정산 열에 남깁니다. 정산 전 경기를 이미 성장에 반영됐다고 표시하지 않습니다.

성장 탭은 시즌별 저장 증감·상승/하락 횟수·기본/추가 성장·2군 리더 훈련·노화·제외 사유를 구분합니다. 도입 전 시즌 시작 스냅샷은 없으므로 **확인된 정산 증감 합계**를 표시하며 시즌 시작 값을 임의로 복원하지 않습니다.

계약·이적 탭은 현재 소속과 실제 최초 지명 기획사·라운드·순번을 표시합니다. 연봉·기간·잔여 시즌·갱신·시장연봉·시장가치·계약금은 실제 저장 원본이 없으므로 `기록 없음`, 미공개 미지명 후보는 `미계약`입니다. 계약된 것으로 추측해 가짜 숫자를 넣지 않습니다.

## 통합 검색·비교

사이드바의 **아이돌 탐색 · 분석**에서 이름·기획사·신분·부상 필터를 사용할 수 있습니다. 나이, CA/추정 CA, 8개 능력치, 건강, 등록 주차, 연속 출전일을 정렬합니다. 비공개 건강·부상 값은 읽거나 정렬 기준으로 사용하지 않습니다.

첫 열의 비교 체크박스로 정확히 두 명을 선택하면 **선택한 2명 비교**가 활성화됩니다. 공통 프로필 두 개를 나란히 표시하며 작은 창에서는 가로 스크롤로 확인합니다. 미공개 후보와 공개 선수의 비교에도 같은 공개 규칙을 적용합니다.

통합 검색은 메뉴에 진입할 때 불러옵니다. 다른 관리 화면을 열 때 미리 200명 분석을 수행하지 않습니다. 날짜나 경기 상태 갱신 시 열려 있는 프로필도 새로 조회하며, 수동 새로고침도 제공합니다.

## 검증 및 한계

새 테스트는 공개/미공개·FA 이력·드래프트 범위·SQL 접근 제한·CA/건강·피로/더블헤더/휴식·위험 배수·정규/특별전/포스트시즌/결정전 집계·성장/노화·동명이인·조회 불변·RNG 불변·검색 정렬·클릭/비교/복귀·작은 창·사진 헤더 겹침 방지·반복 조회를 검증합니다. 원본에 테스트 경기를 생성하지 않았습니다.
