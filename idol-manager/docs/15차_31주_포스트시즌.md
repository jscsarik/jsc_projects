# 15차: 31주 시즌·동률 결정전·포스트시즌

## 실행과 사용

기존 `실행하기.bat`로 실행합니다. 새 게임 생성이나 기존 결과 초기화는 필요하지 않습니다. 기존 저장은 SQLite 백업 후 **DB 버전 10**으로 확장합니다. 실제 원본을 시험 진행하지 않고 복사본과 임시 신규 DB에서 검증했습니다.

정규 24주 일요일의 경기·특별전을 모두 마치고 **하루 진행**을 누르면 다음 월요일에 동률 결정전 또는 포스트시즌 시드를 준비합니다. 사이드바 **포스트시즌**에서 오늘 경기, 출전자 선택, 관전·일시정지·재개·스킵, 저장 결과, 순위와 통산 기록을 조회합니다. 플레이어가 탈락했거나 참가하지 않는 경기도 AI 빠른 진행 또는 개별 관전으로 진행합니다.

## 31주 날짜와 구버전 호환

한 시즌은 **정규 24주(168일) + 포스트시즌 3주(21일) + 비시즌 4주(28일) = 217일**입니다. 0일은 정규 1주 월요일, 168일은 포스트시즌 1주 월요일, 189일은 비시즌 1주 월요일, 217일은 다음 시즌 정규 1주 월요일입니다. 월요일 판단은 기존 공통 함수를 사용합니다.

버전 9까지의 절대일은 196일 시즌 좌표입니다. 변환은 기존 시즌 번호와 정규/비시즌 주차·요일을 유지하도록 시즌당 21일을 삽입합니다. 예를 들어 기존 168일(비시즌 1주 월요일)은 새 189일, 기존 196일(시즌 2 첫 월요일)은 새 217일입니다. 현재 날짜, 출전일·부상일·일일 처리 기록 및 등록 주차를 같은 기준으로 변환합니다. 현재 남아 있는 회복·복귀 제한 기간은 기존 남은 일수를 유지합니다. 이전 상태는 백업 및 `calendar_v9_archive`에 남깁니다.

삽입된 과거 21일 때문에 기존 피로가 자동 초기화되지 않도록, 변환 시점의 최근 출전 간격을 호환 투영합니다. 새 출전부터는 새 절대일을 정상 기록합니다. 기존 부상·등록 누적 수치를 초기화하거나 능력치를 재생성하지 않습니다. 과거 저장된 경기 난수·판정·원본 JSON은 당시 기록으로 유지합니다.

이미 구버전에서 비시즌에 진입했거나 지나간 시즌은 `legacy_closed`로 표시합니다. **지나간 포스트시즌을 소급 생성하거나 우승자를 만들어내지 않습니다.** 이러한 저장은 기존 비시즌 주차부터 계속하며 다음 정규 시즌부터 새 포스트시즌을 진행합니다. 현재 정규 시즌 중인 저장은 이번 시즌부터 새 규칙을 적용합니다.

기존 585경기, 특별전 6회, 더블헤더·콘텐츠·대진은 다시 생성하지 않습니다. 다음 시즌 첫 월요일에만 그 시즌의 기존 정규 일정 생성기를 한 번 호출합니다.

## 정규 최종 순위와 동률 결정전

정규 승점과 특별전 가감점을 합친 최종 점수가 같은 그룹은 하나의 단판 결정전을 치릅니다. 2팀은 정규 1대1 엔진, 3~10팀은 기존 특별전의 공통 성공 판정·동점 추가 판정 루틴을 재사용합니다. 주요 30회·보조 30회와 출전 1군 리더의 추가 2회, 주요 능력치 10회씩의 동점 추가 판정을 유지합니다. 정규 상대 전적이나 성공률로 순위를 대신 결정하지 않습니다.

정규 마지막 일요일 종료 처리 후, 다음 월요일의 자동 교체 전에 1군·리더·부상 상태를 동결합니다. 결정전 중에는 일반 선수단·리더 변경을 서비스에서 막습니다. 마지막 결정전과 부상 판정을 마치고 시드를 확정한 뒤 월요일 운영으로 넘어갑니다.

결정전의 실제 판정과 AI 선택에는 피로 0의 가상 조건을 주입합니다. 원래 연속 출전·출전일 기록은 변경하지 않습니다. 사용자 추가 확정에 따라 **기존 경기 후 부상 확률 판정은 적용**하며, 전용 이벤트 키와 경기 종류를 기록합니다. 실제 부상자는 출전할 수 없고 2군 긴급 출전도 허용하지 않습니다.

정상 출전 팀은 몰수 팀보다 항상 높은 순위입니다. 복수 몰수 팀 또는 전원 몰수 그룹은 정렬된 ID 목록을 균등 셔플하여 순위를 추첨합니다. 경기 시드와 별도 시드 라벨 `forfeit-lottery-v1`, 추첨 순서·사유를 결과에 저장합니다. 조회·재실행 시 재추첨하지 않습니다. 사용자가 순위를 지정하는 기능은 만들지 않았습니다.

이 경기들은 정규 585경기·팀당 117경기 전적·정규 승점·정규 개인 기록에 더하지 않습니다.

## 시드와 3판 2선승제

확정된 정규 최종 1~4위만 참가하며 시드와 최종 순위는 저장 후 재계산하지 않습니다.

| 포스트시즌 | 대진 | 경기일 |
|---|---|---|
| 1주 준플레이오프 | 정규 3위 vs 4위 | 수요일 1차전, 목요일 2차전, 필요 시 금요일 3차전 |
| 2주 플레이오프 | 정규 2위 vs 1주 승자 | 동일 |
| 3주 챔피언 결정전 | 정규 1위 vs 2주 승자 | 동일 |

2승 0패이면 금요일 경기를 생성하지 않습니다. 1승 1패일 때만 3차전을 생성합니다. 라운드 승자는 다음 대진에 연결하며, 결승 2승 팀에 시즌당 하나의 챔피언 트로피를 기록합니다. 정규 1위, 포스트시즌 진출, 최종 챔피언은 서로 다른 기록입니다. 정규 최종 순위와 포스트시즌 최종 배치도 별도로 저장합니다.

기존 30종 콘텐츠에서 선택한 콘텐츠·주요 능력치·양측 공통 필요 인원은 경기 생성 시 저장하여 재조회 때 바뀌지 않습니다. 실제 시각은 추가하지 않았습니다. 플레이어와 AI에게 같은 공개 콘텐츠·일정을 제공하고, 실제 1군·건강·부상·현재 능력치만 사용합니다. 이미 공개된 다음 경기 콘텐츠는 출전자 선택 화면에서도 확인할 수 있습니다.

포스트시즌은 기존 1대1 엔진과 피로·부상을 그대로 적용합니다. 수·목 연속 출전자는 금요일 3일째에 -10%가 적용됩니다. 포스트시즌 진입 시 자동 회복하지 않습니다. 결원은 실제 가능한 인원으로 진행하고 0명일 때만 몰수입니다. 미선택 상태를 몰수로 처리하지 않습니다. 양측 몰수이면 저장된 정규 최종 상위 시드에 시리즈 1승을 부여하고 사유를 저장합니다. 2군 대체·능력치 보너스는 없습니다.

## 금요일 특별 선수단 운영

포스트시즌 금요일, 해당 라운드의 실제 전적이 1승 1패, 3차전 예정 상태, 해당 기획사 참가라는 조건을 모두 만족할 때 교체를 허용합니다. 1군 5명·2군 최대 11명·소속·부상 복귀 제한을 검증하고 새 1군 리더를 지정할 수 있습니다. 시작 후에는 준비된 출전자를 동결하고 변경을 거부합니다. 경기 후 로스터를 자동 복원하지 않습니다. 별도 선수단 잠금 버튼은 없습니다.

AI는 같은 권한 안에서 현재 콘텐츠·능력치·건강·피로·부상으로 1군 후보를 비교하고 필요하면 2군과 교체합니다. 기본 출전 선택은 기존 일정 인식 정책을 사용하며 공개된 다음 경기 정보만 전달합니다. PA·성장 유형·미래 난수 결과는 정책에 전달하지 않습니다. 일반 화·수·목요일 교체는 계속 차단합니다.

## 저장과 재시작 안전성

추가 테이블은 다음과 같습니다.

- `season_finals`: 동결 선수단·정규 승점·최종 순위·시드·챔피언·포스트시즌 최종 배치.
- `final_series`: 라운드별 대진과 승자.
- `final_contests`: 경기 종류·날짜·차수·콘텐츠·필요 인원·준비 입력·시드·상태·결과·판정 이벤트·몰수/추첨 기록.
- `season_honors`: 시즌별 정규 1위·포스트시즌 진출·챔피언 트로피. 중복 키와 시즌당 챔피언 유일 인덱스 적용.
- `calendar_v9_archive`: 구버전 날짜 좌표와 호환 정보.

경기 준비를 먼저 트랜잭션으로 저장하므로 계산 중 종료되어도 같은 출전자·확률·시드로 재개합니다. 결과·부상·시리즈·다음 대진·트로피는 하나의 최종 트랜잭션으로 반영합니다. 실패하면 모두 롤백합니다. 동시 요청은 SQLite 쓰기 잠금과 완료 상태 재검증으로 중복 반영하지 않습니다. 완료 결과는 조회만 합니다.

날짜 서비스는 기존 미처리 정규·특별전 차단에 결정전·포스트시즌을 추가했습니다. 미완료 결승을 건너 비시즌으로 진행하지 않습니다. 탈락 팀의 게임 날짜도 같은 달력으로 진행하며, 남은 AI 경기는 실제 판정을 거칩니다.

## UI·BGM

14차 `MatchPage`·`BattleView`·썸네일·저장 이벤트 재생을 어댑터로 재사용합니다. 사진·VS·리더 배지·성공/실패 애니메이션·로그·시리즈 전적·진출 팀·스킵·일시정지·재개를 제공합니다. 순위와 기획사 통산 기록 탭도 제공합니다. 관전은 기존 battle, 결과/관리 화면은 default BGM이며 새 카테고리는 없습니다.
