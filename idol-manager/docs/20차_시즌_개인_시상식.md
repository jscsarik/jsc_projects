## 2. MVP

정규 경기 승리 아이돌 횟수 최다. 기존 확정 승리·패배 아이돌은 그대로 사용합니다. 누락된 선정 기록만 저장된 일반 판정 성공/실패로 복구하고 기존 `choose_award` 동률 정책을 재사용하여 보조 원장에 1회 저장합니다. 경기 원본·요약·이벤트를 수정하지 않습니다. 패배 아이돌 횟수는 감점하지 않습니다.

프로 선수의 실제 0회 기록도 포함하며, MVP·신인왕에 요청서에 없는 최소 출전 조건을 추가하지 않았습니다. 실질적인 시상 기준 기록 자체가 없는 경우에는 임의 수상자를 만들지 않습니다.

## 3. 신인왕

19차 `market_careers.debut_season`과 최초 드래프트의 확정 시즌 1 기록을 사용합니다. 연습생 기간·새 계약·FA·트레이드를 새로운 프로 데뷔로 간주하지 않습니다. 대상 시즌에 처음 데뷔한 프로 중 승리 아이돌 최다. 필요 데뷔 기록이 확인되지 않으면 임의로 만들지 않고 문제를 안내합니다.

## 4. 리더상

정규 경기의 `leader` 단계 실제 성공만 합산합니다. 추가 시도·성공·리더 출전 경기·성공률을 보존합니다. 일반 리더십 판정은 제외합니다.

## 5. 매력상 8종

능력치별 실제 일반 시도 횟수 상위 최대 5명 중 성공률 최고가 수상합니다. 시도 0은 제외합니다. 주요·무작위 그룹에서 실제 사용된 능력치를 합산합니다. 성공률 순서는 `Fraction(성공, 시도)`의 정확한 유리수 비교로 결정하고, 화면 표시만 소수 둘째 자리로 반올림합니다. 후보별 시도·성공·실패·성공률을 비교할 수 있습니다.

## 6. 17차 판정 데이터

`scheduled_matches`의 해당 시즌 완료 정규 경기와 `match_player_stats`·`match_events`를 사용합니다. 일반 판정 60회 및 주요/무작위 30회, 리더 추가 시도/성공이 기존 요약과 일치하는지 검사합니다. 기획사별 결과와 대진 소속의 누락도 확인합니다. 경기 재실행·이벤트 재추첨·CA/PA 조회는 없습니다.

특별전, 포스트시즌, 최종 순위 결정전, 데스매치는 개인상 집계에서 제외합니다. '연말시상식'이라는 정규 콘텐츠는 다른 정규 콘텐츠와 같은 공식 경기이고, 별도 개인 시상식 기능과 혼동하지 않습니다.

## 7. 동률·이적 소속

확정된 `season_finals.final_order_json`의 정규 순위를 우선합니다. 포스트시즌 우승은 가산하지 않습니다. 동일 기획사 동률은 동일 확률의 셔플 추첨이며 시즌 seed·추첨 풀·확정 순서를 저장합니다. 매력상 5위 경계와 성공률 동률에 각각 적용합니다. 같은 선수가 여러 상을 받아도 됩니다.

정규 24주 종료 시 소속/데뷔 스냅샷을 저장합니다. 과거 종료 시점은 일별 소속·시장 이동 기록·정규 종료 동결 명단 등 입증 가능한 기록으로 복구합니다. 종료 당시 FA는 마지막 실제 정규 출전 팀을 사용합니다. 선정에 필요한 소속을 객관적으로 확인할 수 없으면 확정을 중단합니다. 정규 종료 기준 팀과 실제 수상 당시 팀은 별도 필드입니다.

## 8. UI와 프로필

왼쪽 또는 세로형 상단 메뉴 **시즌 개인 시상식**을 엽니다. 시즌 선택으로 역대 기록을 조회합니다.

- 주요 개인상: 큰 MVP 사진 카드, 신인왕·리더상 카드.
- 매력상 8종: 4장씩 두 페이지. 900×1600 세로형과 작은 창의 가독성을 위해 11장을 무조건 한 화면에 축소하지 않습니다.
- 정규 개인 기록: 모든 프로의 출전·팀 승패·승리/패배 아이돌·리더 추가·8개 능력치 시도/성공. 시즌 중에는 미확정 통계 조회만 가능합니다.
- 기획사·역대 수상: 수상 당시 기획사 필터, 선택 시즌/통산 합계, 상별 횟수와 과거 수상 목록.
- 카드 사진/이름: 기존 공통 프로필. 선정 근거 버튼: 확정 후보·통계·소속별 기여·추첨 기록 존재 여부.

사진은 기존 원본을 읽어 전용 썸네일 캐시를 생성합니다. 사진 누락 시 기존 대체 이미지를 사용합니다. 외부 이미지 API·유료 서비스·상금·급여 보너스는 추가하지 않았습니다.

## 9. 수상 이력

공통 프로필 계약·경력에 시즌·상·당시 팀·정규 기준 순위·기록·확정 날짜를 표시하고 11종 통산 횟수를 집계합니다. 이적·FA·방출·은퇴 후에도 기존 수상 팀이나 수상 기록을 덮어쓰지 않습니다. 팀 우승 트로피는 기존 `season_honors`에 따로 유지합니다.

## 10. 저장·시즌 종료

DB 버전은 **14**입니다. 추가 테이블은 네 개입니다.

- `award_regular_rosters`: 정규 종료 기준 소속/데뷔 스냅샷.
- `award_match_selections`: 기존 경기 선정 기록의 복구 가능한 누락만 보존하는 보조 원장.
- `season_awards`: 시즌당 1개 확정 배치, seed·날짜·정규 1위·챔피언·개인 시즌 통계 스냅샷.
- `individual_awards`: `(season, award_type)` 고유 키, 수상자·두 소속·순위·선정 근거·후보·추첨 기록.

기존 DB의 행은 변경하지 않는 추가 마이그레이션이며, 적용 전에 SQLite 백업을 만듭니다. 같은 시즌 재실행은 저장된 결과를 반환합니다. 동시 요청은 `BEGIN IMMEDIATE`, 11개 결과·추첨·복구·배치의 원자성은 트랜잭션/세이브포인트로 보장합니다.

결승 완료 후 자동 확정하며, 관전이 끝나거나 AI 진행이 끝나면 시상식으로 안내합니다. 필수 데이터가 누락되어도 완료된 결승을 취소하지는 않습니다. 대신 시상식에서 이유를 알리고, 비시즌 첫 주의 성장·재정·시장 처리가 시작되기 전에 시상 확정을 다시 검증하여 불완전한 상태로 넘어가지 못하게 합니다.

## 12. 기존 세이브 보존

작업 시작 백업: `data/backups/idol_manager_before_awards20_20261029_003407.sqlite3`.

이 백업의 복사본을 DB 14로 마이그레이션한 뒤 모든 기존 테이블의 모든 행 해시가 동일하고, SQLite 무결성/외래 키가 정상임을 확인했습니다. 원본에 테스트 결과나 수상자를 생성하지 않았습니다.

작업 중 실제 게임은 `absolute_day=55, revision=56`에서 `56,57`로 진행되었습니다. 사용자의 실제 플레이 상태를 시작 백업으로 되돌리지 않았습니다. 마지막 원본 읽기 전용 확인 당시 DB는 13이었고 무결성 정상/외래 키 오류 없음입니다. 실행 중인 앱을 종료하고 다시 열면 백업 후 DB 14로 확장합니다. 기존 사진·음악을 수정하거나 이름을 바꾸지 않았습니다.

## 13. 이번에 하지 않은 검증/기능

- 장기 시즌 자동 시뮬레이션, 10~20시즌 반복, 밸런스·대규모 성능 검사는 실행하지 않았습니다.
- 실제 세이브의 정규 585경기와 포스트시즌을 끝까지 새로 진행하지 않았습니다. 종료 연동은 작은 고정 DB로 확인했습니다.
- 새 드래프트·FA/트레이드 AI 재작성·경기/부상/성장 수치 변경·새 시상식 상금은 구현하지 않았습니다.

- 모든 과거 세이브의 불완전 기록을 추측하여 복구하는 기능은 없습니다. 저장된 사실로 입증되는 범위만 사용합니다.

게임을 완전히 종료한 뒤 프로젝트의 `실행하기.bat`으로 다시 실행하고 **시즌 개인 시상식** 메뉴를 선택하세요. 새 게임 생성은 필요하지 않습니다.
