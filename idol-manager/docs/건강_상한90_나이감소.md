# 건강 상한 90·나이 증가 시 건강 감소

20차 시상식 구현은 유지하고 건강 규칙만 추가했습니다.

## 적용 규칙

- 신규 생성: 기존 `config/generation.json`의 건강 추첨 범위 **65~100은 원래 분포를 보존하기 위한 추첨 범위**입니다. 원래와 같은 난수를 뽑은 뒤 90 초과만 90으로 잘라 저장합니다. 65~90으로 다시 균등 추첨하지 않습니다. 나이가 많게 생성됐다고 소급 차감하지 않습니다.
- 현재 저장 데이터: DB **15** 마이그레이션에서 `health>90`만 90으로 조정합니다. 원본 DB를 먼저 SQLite 백업하며, DB 버전으로 중복 적용을 막습니다. 기존 부모 테이블을 재작성하지 않고 INSERT/UPDATE 범위 트리거로 정수 0~90을 보장합니다.
- 이후 생일: 기존 비시즌 1주차 월요일의 나이 정산에서 실제 증가 나이만큼 건강을 내립니다. 나이 +1이면 건강 -1, 최저 0입니다. 기존 생일 정산 고유 키와 `BEGIN IMMEDIATE`를 이용해 동일 시즌 중복·동시 요청을 막습니다. 나이와 건강 및 감사 기록을 한 트랜잭션에서 저장합니다.
- 과거 생일/현재 나이에 대한 소급 차감은 없습니다. 이전 버전에서 이미 저장한 생일 정산도 다시 적용하지 않습니다.
- 건강은 8개 CA·PA와 별도입니다. 이번 생일 건강 감소만으로 8개 능력치나 평균을 바꾸지 않습니다.
- 부상 시 추가 건강 감소, 2군 휴식 시 건강 회복, 새로운 건강 훈련은 추가하지 않았습니다.
- 기존 `(100-건강)` 부상 확률 공식, 연속 1군 등록 배수, 휴식/복귀 규칙, AI 평가 가중치는 그대로입니다. 새로운 현재 건강값을 기존 서비스에서 읽습니다. 90을 100처럼 환산하지 않습니다.

## 코드 변경

- `idol_manager/health_rules.py`: 상한·실제 나이 증가에 따른 감소·DB 15 트리거.
- `idol_manager/domain.py`: 기존 추첨 후 상한 적용.
- `idol_manager/migrations.py`: 백업을 동반한 일회성 DB 15 마이그레이션.
- `idol_manager/development_service.py`: 기존 생일 정산에 건강 감소 결합. `facts_json`에 `health_before`, `health_after`, `health_change` 저장.
- `idol_manager/ui/profile_dialog.py`: 프로필 건강 표시에 `/90` 추가. 비공개 후보는 계속 미공개입니다.
- `tests/test_health90.py`: 아래 핵심 8개 검사.
- 공유 테스트 준비 코드 `tests/game_fixtures.py`, `tests/test_match_ui.py`, `tests/migration_fixtures.py`: 더 이상 허용되지 않는 건강 100을 만들지 않고, 구형 스키마 재현 시 새 범위 트리거를 함께 제거하도록 조정.
- README와 이 문서.

검색·비교·선수단·출전 DTO·AI는 기존 DB 조회 경로를 그대로 재사용합니다. 부상 확률 코드/능력치 판정/시상식 기준을 바꾸지 않았습니다.

## 검증

핵심 **8개 모두 통과**, 9.432초:

1. 신규 생성 0~90, 원래 난수/분포/나이/능력치가 상한 처리 외에 동일.
2. DB 백업·상한 조정·기존 수상 행 보존·범위 위반 차단·재실행 무변경·무결성.
3. 나이 +1에 정확히 건강 -1 및 감사 기록.
4. 같은 시즌 동시/반복/재실행 중복 감소 방지 및 구형 생일 소급 차감 금지.
5. 건강 0/1의 하한, 다음 시즌에도 0 미만 감소 금지.
6. 건강 감소 시 8개 CA/PA/평균 유지.
7. 기존 부상 공식/연속 등록 위험 배수/휴식 필요 주차 유지.
8. 프로필·검색/비교 API·선수단·경기 출전 DTO의 건강이 DB와 일치.

추가로 실제 세이브의 **백업 복사본**을 DB 15로 업그레이드했습니다. 건강 초과 96명을 90으로 조정했고, 모든 기존 테이블의 모든 값이 요청한 건강 상한 처리 외에는 동일했습니다. 무결성 `ok`, 외래 키 오류 없음, 두 번째 마이그레이션 무변경, 실제 프로필/출전 DTO 일치를 확인했습니다.

- 테스트 로그: `.test-artifacts/health90_tests.log`
- 실제 백업 복사본 검증: `.test-artifacts/health90_preservation.json`
- 변경 전 백업: `data/backups/idol_manager_before_health90_20261029_010342.sqlite3`

장기 자동 시뮬레이션, 20차 전체 재개발, 전체 테스트 반복, 새 GUI 자동화는 수행하지 않았습니다. 프로필 등 연동은 실제 데이터 조회 API로 확인했습니다. 이미 완료/준비 저장된 경기의 과거 판정 및 입력 스냅샷은 다시 계산하거나 덮어쓰지 않습니다. 새로 준비하는 경기는 현재 DB의 건강을 사용합니다.

## 실행

실행 중인 게임을 완전히 종료하고 `실행하기.bat`으로 다시 실행하세요. 기존 세이브를 새로 만들 필요는 없습니다. 시작 시 백업 후 DB 15로 확장하고 90 초과 건강만 자동 보정합니다. 이 작업에서 원본에 테스트 결과나 가상 생일을 적용하지 않았습니다.
