# 12차 특별전 엔진·UI

기존 28주 체계(정규 24주 + 비시즌 4주), 정규 585경기, 특별전 6개의 ID·종류·날짜를 유지합니다. 실제 세이브를 대신 진행하지 않습니다. 다음 실행 시 백업 후 버전 8로 추가 마이그레이션합니다.

## 게임에서 진행하는 방법

1. 기존대로 드래프트·선수단·리더를 확정하고 정규 경기를 진행합니다.
2. 정규 4·8·12·16·20·24주차 일요일에 사이드바 **특별전** 또는 일정표 아래 **특별전 화면 열기**를 누릅니다.
3. **그룹 편성 확정**을 누르면 그 시점의 리그 순위와 상위/하위 5개 기획사가 영구 저장됩니다.
4. 플레이어가 참가하는 그룹에서 건강한 1군을 우선 포함하고 2군을 추가해 총 10명을 선택합니다. 10명 미만만 가능하면 가능한 인원 전원을 선택합니다. 부상자는 회색으로 표시하며 선택할 수 없습니다.
5. **대결 시작**으로 해당 그룹을 진행합니다. 다른 그룹도 같은 화면에서 AI 출전자로 진행합니다. 두 그룹을 모두 마치면 후속 4자 대결이 나타납니다.
6. 후속에서는 **최초 출전자 10명 중 부상자를 제외하고 1군 우선, 부족분은 2군**으로 콘텐츠 인원만큼 선택합니다. 이는 이번 대화에서 확인한 규칙입니다. 처음 참가하지 않은 예비 선수는 새로 투입할 수 없습니다.
7. 각 단계는 약 15초 관전하거나 스킵할 수 있습니다. 이미 저장된 이벤트를 보여주므로 판정이나 부상·승점을 다시 추첨하지 않습니다. 동률 추가 판정은 연출 시간이 추가될 수 있습니다.
8. 세 단계가 모두 완료되면 일정 상태가 완료로 바뀌며 다음 월요일로 진행할 수 있습니다. 과거 특별전은 목록에서 선택해 단계별 결과를 다시 볼 수 있습니다.

**특별전 최종 정리 · 10개 기획사** 탭은 각 기획사의 최초 그룹, 확정 그룹 순위, 후속 순위와 그룹/후속/총 승점 변동을 한 표로 제공합니다.

## 판정과 순위

| 종류 | 주요 능력치 |
|---|---|
| 대학축제 | 예능·외모·신체 |
| K-POP 페스티벌 | 보컬·댄스·랩 |
| 아이돌 체육대회 | 리더십·예능·신체 |

5자 대결은 선수당 주요 15회(3종 각 5회) + 보조 15회입니다. 후속 4자 대결은 기존 30종 콘텐츠 중 한 종류와 공통 필요 인원을 한 번만 확정해 저장하고, 선수당 주요 30회 + 보조 30회로 진행합니다. 후속의 연말시상식도 기존 30종 중 하나로 추첨 가능하며, 정규 일정의 21~24주 제한을 특별전 추첨에 임의로 확장하지 않았습니다.

실제 출전한 1군 리더는 리더십 추가 2회, 실제 출전한 2군 리더는 추가 1회입니다. 특별전 두 단계 모두 동일하게 적용합니다. 리더가 출전하지 않으면 추가 판정이 없습니다. 주요·보조·리더·동률 판정은 구분해 저장합니다.

기본 성공 합계로 순위를 나누고 동률 기획사만 실제 출전자 대표 1명으로 주요 능력치 10회를 판정합니다. 대표는 기존 정규 경기 대표 정책을 재사용합니다. 5명 콘텐츠에서 실제 출전한 1군 리더를 우선하고, 그 외에는 피로를 반영한 주요 능력치가 가장 좋은 선수를 선택합니다. 추가 판정에는 리더 보너스가 없습니다. 한 차례에 분리된 순위 블록은 이후 다른 동률 블록의 추가 점수로 뒤집지 않습니다. 따라서 추가 성공 횟수의 단순 총합이 아니라 저장된 최종 순위와 판정 차수로 결과를 해석해야 합니다.

항상 같은 결과만 가능한 0%/100% 대표 조합이나 동률 1,000회 반복 예외는 임의 승자를 만들지 않고 해당 단계를 차단하고 이유를 안내합니다. 일반적인 결원은 이 예외와 구분합니다.

### 몰수와 결원 정책

사용자가 확인한 대로 **몰수 팀은 실제 출전 팀보다 최하위**에 배치합니다. 가능한 선수가 적어도 1명 있으면 그 인원으로 실제 판정합니다. 전원 결원인 팀에는 가짜 출전자·대표·판정 이벤트를 만들지 않습니다.

복수 몰수 사이에는 판정으로 우열을 만들 수 없으므로, 이미 저장된 특별전 시작 시 임시 리그 순위를 행정 정렬 기준으로 사용합니다. 몰수 팀에는 양수 승점을 주지 않으며, 최하위에 따른 기존 -2점 규칙은 유지합니다. 후속 진출은 저장된 상위 그룹 4·5위 / 하위 그룹 1·2위로 정하고 새 기획사를 대신 넣지 않습니다. 진출 팀이 전원 결원이면 후속에서도 같은 몰수 규칙을 적용하므로 단계가 영구 중단되지 않습니다. 별도의 몰수 보상은 없습니다.

## 그룹 및 승점

리그 승점은 **정규 승점 + 특별전 승점**입니다. 정규 승패·117경기 기록은 수정하지 않습니다. 중간 그룹 편성은 현재의 결정적 임시 기준인 **합계 승점 내림차순, 기획사 ID 오름차순**을 사용합니다. 최종 시즌 동률 결정전은 구현하지 않았습니다. 한 번 시작한 그룹은 이후 승점 변동으로 바뀌지 않습니다.

| 단계 | 승점 |
|---|---|
| 상위 5자 | 1위 +2, 2위 +1, 그 외 0 |
| 하위 5자 | 5위 -2, 그 외 0 |
| 후속 4자 | 하위 그룹 출신 1위 +2, 상위 그룹 출신 4위 -2, 나머지 0 |

각 단계의 가감점은 별도 장부에 한 번만 저장합니다. 기본 점수와 후속 점수는 합치지 않으며, 리그 승점만 합산합니다. 단계 결과가 확정된 승점은 순위표에 반영하지만 해당 특별전의 남은 단계가 있으면 날짜 진행은 계속 차단됩니다.

## 피로·부상 및 저장 안전성

11차의 `public_condition`, `record_appearance`, `injury_probability`, `risk_event`와 공통 실제 출전 확정 함수를 사용합니다. 원본 능력치·건강은 바꾸지 않습니다. 최초 그룹과 후속에 모두 출전해도 같은 날짜 출전일은 한 번만 증가하며 부상 위험은 실제 경기마다 별도로 판정합니다. 첫 그룹에서 부상당한 선수는 후속에서 제외됩니다. 실제 출전한 2군도 경기 부상 공식을 사용하고, 그날 미출전 일일 위험은 중복 적용하지 않습니다.

경기 준비는 공개 현재 능력치·피로·출전자·리더·적용 확률·시드를 고정해 저장합니다. 결과 확정은 팀 순위, 선수·능력치별 기록, 이벤트, 가감점, 피로·부상, 후속 단계 생성 및 전체 완료 상태를 하나의 SQLite 트랜잭션으로 처리합니다. 저장 실패나 강제 종료로 일부만 반영되지 않습니다. 완료된 단계는 재계산하지 않습니다. 동시 요청은 `BEGIN IMMEDIATE`와 유일 키로 보호합니다.

AI는 공개 현재 능력치·건강·현재 피로·부상과 해당 단계의 공개 콘텐츠만 사용합니다. 1군을 우선하고, 주요·보조·실제 출전 리더의 기대 성공 수로 후보를 평가합니다. 잠재력·성장 유형·미래 추첨·상대의 비공개 선택은 조회하지 않습니다. 최초 그룹 선발 시 아직 확정되지 않은 후속 콘텐츠는 보지 않습니다.

## DB 버전 8

기존 테이블의 열이나 기존 행을 변경하지 않는 추가형 마이그레이션입니다.

| 신규 테이블 | 역할 |
|---|---|
| `special_sessions` | 시작 순위, 상·하위 그룹, 버전과 세션 시드 |
| `special_rounds` | 3단계 구성, 공통 콘텐츠·인원, 준비 입력·시드, 상태와 결과 |
| `special_team_results` | 단계별 기획사 순위, 기본·추가 점수, 몰수 |
| `special_player_stats` | 실제 출전, 주요·보조·리더·동률 개인 기록 |
| `special_ability_stats` | 선수·능력치·판정 종류별 시도/성공/실패 |
| `special_judgments` | 재생 가능한 모든 판정의 순서·확률·난수·결과 |
| `special_points` | 특별전·기획사·단계별 유일한 승점 장부 |

`special_standings`, `idol_special_career_stats` 뷰를 추가합니다. 정규 경기의 기록·통산 뷰와 특별전 기록은 분리합니다. `SpecialService.player_records()`로 특별전 개인 이력을 조회할 수 있습니다.

## 검증 방법

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe tools/verify_special_season.py
.\.venv\Scripts\python.exe tools/verify_special_ui.py
```

모든 개발·검증은 임시 DB와 복사본에서 실행합니다. 마지막 명령은 Windows 네이티브 Qt 창을 표시합니다. BGM 상황 전환은 제어 가능한 가짜 오디오 백엔드로 확인하며 실제 Qt 오디오 디코더는 기존 BGM 회귀 테스트가 별도로 검사합니다. 사람의 청취 검증을 의미하지 않습니다.

## 현재 검증 결과와 보존 상태
