# 창단 준비와 월요일 연습생 자유계약

이번 변경은 소스 실행본에 적용됩니다. 프로젝트의 `실행하기.bat` 또는 `.venv\Scripts\python.exe main.py`로 실행하세요. 배포 폴더의 기존 0.28.0 EXE/ZIP은 그대로 보존되어 이번 변경을 포함하지 않습니다. DB 18로 업그레이드한 세이브는 이 소스 버전으로 실행하세요. DB 17용 구형 EXE로 같은 세이브를 다시 열 수 없으므로 이전 버전이 필요하면 별도 보관한 업그레이드 전 백업을 사용해야 합니다.

## 새 게임 흐름

1. 최초 드래프트 160회 지명을 완료합니다. 새 게임에서만 **창단 준비 1/7일 · 월요일**로 진입합니다.
2. 선수 시장 → 계약 협상에서 플레이어의 1~3라운드 지명 계약 3건을 선택해 기존 협상 규칙(최대 3회·거절 후 5% 인상·1~2시즌)에 따라 제안합니다. 4~16라운드는 기존 확정 규칙인 연봉 3,000만 원·1시즌으로 자동 계약합니다.
3. 상위 지명 협상을 포기하거나 3회 실패하면 해당 선수는 FA로 이동합니다. 선수 시장 → FA 시장 → **직접 협상**으로 프로 16명 결원을 보충합니다. 준비 기간에는 2일짜리 공개 입찰을 사용할 수 없습니다.
4. 같은 준비 월요일에 1군 5명·2군 11명을 편성하고 두 리더를 지정합니다. AI 9곳은 공개 정보와 기존 계약·편성 정책으로 준비합니다.
5. 필수 계약·편성·두 리더가 모두 완료되어야 첫 화요일로 넘어갑니다. 준비 기간의 편성·리더 지정도 월요일에만 가능합니다.
6. 준비 일요일 다음 날은 **시즌 1 · 정규 1주차 · 월요일**입니다. 기존 31주/217일 시즌 구조는 그대로입니다. 정규 일정 585경기와 특별전 6회는 이때 생성합니다.

준비 7일에는 정규 경기·주간 성장·급여 정산을 실행하지 않습니다. 1군 등록 위험·2군 휴식 일수에도 준비 기간을 누적하지 않습니다.

## 매주 연습생 신청

선수 시장 → **연습생 영입·데뷔**에서 후보를 선택하고 **이번 월요일 신청 추가**를 누릅니다. 현재 신청 `0/2`, `1/2`, `2/2`와 후보 이름이 표시됩니다. 마감 전에는 선택 후보 취소·전체 취소 후 다른 후보로 변경할 수 있습니다.

- 각 기획사는 같은 월요일 서로 다른 후보 최대 2명에게 신청합니다. 총 연습생 보유 수는 제한하지 않습니다.
- 연봉은 0원이며 기존 정규 시즌 주간 관리비 10만 원 규칙을 사용합니다.
- **하루 진행**을 누르면 신청자 수와 이름을 확인하는 마감 창이 표시됩니다. 0명 신청도 명시적으로 확인합니다. 취소하면 날짜·신청·난수·소속을 변경하지 않습니다.
- 승인하면 AI 9곳의 신청을 함께 수집한 뒤 후보별 동시 추첨합니다. 한 후보의 신청 기획사가 N곳이면 각 1/N입니다. 제출 순서에 우선권이 없습니다.
- 결과가 확정되면 **마감 결과 확인**에서 영입 팀과 전체 신청 기획사를 확인할 수 있습니다. 마감 전에는 다른 팀 신청을 공개하지 않습니다.
- 실패한 신청도 해당 월요일의 신청으로 남습니다. 마감 후에는 변경·재추첨할 수 없습니다.
- 후보가 다른 계약으로 소속을 얻거나 계약 예산 검증을 통과하지 못하면 실패 기록을 남기고 다른 팀에게 재추첨하지 않습니다.

대상은 공개된 **최초 미지명자 40명**과 이후 연간 드래프트에서 미지명이 확정된 공개 후보입니다. 연간 드래프트 이전에 신인을 자유계약으로 선점하지 않습니다. 17세 이상 미지명 신인도 가능하지만 기존 프로 경력자·소속 선수·은퇴자·진행 중인 FA 입찰 또는 프로 협상 대상은 제외합니다.

AI 신청 정책은 이름·사진 경로·나이·ID만 포함한 `BlindCandidate`를 받아 최대 2명을 선택합니다. PA와 특별 유망주 정보는 조회하지 않습니다.

## 저장과 기존 세이브

DB 18은 마이그레이션 전 SQLite 백업을 만들고 8개 테이블만 추가합니다. 기존 세이브에는 창단 준비 행을 만들지 않으므로 날짜·기존 만료일 미정 계약을 소급 변경하지 않습니다. 기존에 영입한 연습생도 보존합니다.

`founding_setup`은 새 게임의 대기/준비/완료와 준비 일차를 저장합니다. 기존 `game_clock.absolute_day`는 준비 중 0을 유지하며, 날짜 서비스가 준비 -7~-1일을 반환합니다. 정규 첫 월요일 이후는 기존 0~216일 순환을 그대로 사용합니다.

`trainee_rng`에 난수 상태, `trainee_weeks`에 마감 전후 난수 상태, `trainee_sheets`와 `trainee_applications`에 신청·수정 버전, `trainee_results`에 신청 기획사·추첨 위치·결과, `trainee_submission_keys`에 중복 요청 ID를 저장합니다. `founding_contracts`는 기존 협상 ID와 상위 지명 계약 처리 상태를 연결합니다.

마감·영입·난수 갱신·날짜 진행은 하나의 `BEGIN IMMEDIATE` 트랜잭션입니다. 날짜/신청 수정 버전 충돌을 차단하며 저장 실패 시 전체 롤백합니다. 저장 후 결과를 다시 열거나 재시도해도 기존 결과를 반환합니다.

AI 재계약 뒤 선택적 트레이드 거절로 정상 계약 제안까지 취소되던 저장 경계도 수정했습니다. 협상 확률·선수 평가·금액 규칙은 유지하고, 날짜 진행 자체의 저장 실패에는 여전히 전체 롤백합니다.

## 검증

최종 자동 테스트 결과와 전체 수정 파일 목록은 `reports/founding_preparation/RESULTS.md` 및 `modified_files.json`을 확인하세요. 모든 게임 테스트는 임시 DB 또는 복사본을 사용합니다. 실제 프로젝트 세이브와 AppData 세이브는 작업 전 백업과 논리 해시가 일치하며 원본 자산·설정 541개 파일의 SHA-256도 일치했습니다.
