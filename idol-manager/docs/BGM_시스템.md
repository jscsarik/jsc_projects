# BGM 시스템과 화면 연동

## 음악 폴더와 사용법

아래 두 폴더에 **MP3 또는 WAV**를 넣습니다. 대소문자를 구분하지 않으며 한글·영문·숫자·공백 파일명을 지원합니다. 폴더가 없으면 실행 시 백그라운드에서 만듭니다. 폴더 바로 아래 파일을 검색하며 하위 폴더는 재귀 검색하지 않습니다.

```text
C:\정승찬\IDOL_Manager\assets\audio\bgm\default\
C:\정승찬\IDOL_Manager\assets\audio\bgm\battle\
```

현재 프로젝트에는 일반 18곡·배틀 13곡이 있습니다. 곡명은 코드에 등록하지 않습니다. 파일을 추가·삭제한 뒤 다음 실행을 기다리거나 상단 **♪ BGM → 음악 목록 새로고침**을 누르면 반영됩니다. 검색에는 개수 제한을 두지 않았고 목록 정리는 선형 방식으로 처리합니다. 실제 재생에는 프로젝트 기준으로 해석한 절대 경로와 `QUrl.fromLocalFile()`만 사용합니다. 다운로드·스트리밍·원본 변환 기능은 없습니다.

상단의 작은 **♪ BGM** 버튼에서 다음을 조작합니다.

- **BGM 켜기:** 전체 배경음 사용 여부. 끄면 재생 자원을 정지하고 켜면 현재 상황의 음악을 재생합니다.
- **음소거:** 재생 위치는 계속 진행하고 소리만 끕니다.
- **일시정지 / 재생:** 현재 음악 위치에서 중지·재개합니다. 일시정지한 채 상황이 바뀌어도 자동으로 소리를 켜지 않습니다.
- **볼륨 0~100%:** 즉시 적용됩니다.
- **다음 곡:** 현재 카테고리의 다음 셔플 곡을 선택합니다.
- **음악 목록 새로고침:** 파일 추가·삭제를 다시 검색합니다.

볼륨·음소거·켜기 상태는 `data/bgm_settings.json`에 원자적으로 저장합니다. SQLite에는 음악이나 음악 설정을 등록하지 않습니다. 일시정지는 현재 실행 중에 유지하고, 다음 앱 실행의 재생 여부는 저장된 BGM 켜기 상태를 따릅니다. 새 게임을 만들어도 음악 설정은 지워지지 않습니다.

## 관리 구조

`app.run()`이 `BgmManager` 한 개를 `QApplication` 소유로 생성하여 메인 창에 주입합니다. 화면마다 플레이어를 만들지 않습니다. 개별 창을 사용하는 테스트에서도 창 수명 동안 하나의 관리 객체를 재사용합니다.

| 파일 | 책임 |
| --- | --- |
| `idol_manager/bgm_catalog.py` | 로컬 파일 탐색, 제목 해석, 카테고리별 셔플 백 |
| `idol_manager/bgm.py` | 공통 상태, 백그라운드 목록 갱신, 카테고리 전환·페이드·오류 처리·설정 저장 |
| `idol_manager/bgm_backend.py` | 지연 로딩하는 단일 `QMediaPlayer`·`QAudioOutput` 어댑터 |
| `idol_manager/ui/bgm_controls.py` | 상단 음악 메뉴와 마우스 투과 알림 |
| `idol_manager/app.py` | 앱 공통 객체 생성·종료 |
| `idol_manager/ui/main_window.py` | 공통 메뉴·알림과 실제 페이지 상태 연동 |
| `idol_manager/ui/match_page.py` | 기존 관전 시작·종료 상태 신호만 추가 |
| `tests/test_bgm.py` | 목록·셔플·예외·설정·조작 UI·알림·화면 연동 테스트 |
| `tests/test_bgm_native.py` | 실제 손상 MP3 회피·한글 WAV 재생·곡 종료 반복 검증 |
| `tests/test_match_ui.py` | 실제 경기 판정/관전 상태에 대한 BGM 연동 검증 추가 |
| `tools/verify_bgm_playback.py` | 원본 DB를 건드리지 않는 Windows MP3 출력 장치·디코딩 진단 |
| `README.md`, 이 문서 | 사용법과 검증 보고 |

음악 검색·폴더 생성·파일 상태 읽기는 전용 작업 스레드에서 처리합니다. 디코딩은 Qt Multimedia 백엔드가 담당합니다. 디코더의 콜백은 명시적인 Qt queued slot으로 UI 스레드에 전달해 플레이어 제어와 충돌하지 않도록 했습니다. 곡 변경 시 약 0.6초의 음량 페이드를 적용하고 빠른 화면 전환은 120ms 동안 합칩니다. 같은 카테고리의 화면 전환은 플레이어·재생 위치·곡을 유지합니다.

두 카테고리의 셔플 백은 별도로 보관합니다. 한 순환의 모든 곡을 한 번씩 소비한 뒤 다시 섞고, 두 곡 이상이면 순환 경계에서도 직전 곡의 연속 재생을 피합니다. 1곡이면 반복합니다. 배틀에서 일반으로 돌아오면 일반 셔플 백의 다음 곡을 선택합니다. 앱 재실행 시에는 새 셔플 백을 만들며 재생 순서와 위치는 저장하지 않습니다.

## 실제 화면 상태와 연결

**DEFAULT:** 메인·후보 명단·기획사 명단·드래프트·선수단·일정·순위표·출전자 선택·경기 결과·AI 빠른 진행 화면입니다.

**BATTLE:** 기존 `MatchPage`가 저장된 경기 이벤트를 실제로 재생 중이며, 현재 페이지와 활성 탭이 **경기 진행**일 때만 사용합니다. 경기 시작 버튼을 누른 뒤 계산 중인 시간에는 DEFAULT를 유지합니다. 경기 탭에서 순위표로 이동하면 DEFAULT, 관전 탭으로 돌아오면 BATTLE, 종료·스킵 후 결과 탭에서는 DEFAULT로 복귀합니다. 결과 조회만으로 배틀을 생성하거나 판정을 호출하지 않습니다.

아직 없는 특별전·포스트시즌·기타 배틀 화면은 만들지 않았습니다. 향후 실제 화면의 상태 전환에서 `bgm.set_context('battle')`, `bgm.set_context('default')` API를 연결하면 됩니다. 현재 메인 창의 자동 판단도 새 배틀 화면에 맞춰 확장해야 합니다.

## 음악 정보 알림

유효한 새 음악이 실제 재생되기 시작하면 `♪ 아티스트 — 곡명`을 창 상단에 보여줍니다. 기본 1.5초 후 0.3초 동안 페이드아웃합니다. 확인 버튼과 포커스 이동이 없고 마우스 이벤트는 통과합니다. 단순 화면 전환·음량 변경·같은 곡의 일시정지/재개에는 새 알림을 띄우지 않습니다.

`아티스트 - 곡명 (Inst.).mp3`처럼 공백을 포함한 구분자로 안전하게 나눌 수 있으면 아티스트·곡명으로 표시합니다. 안전하게 나눌 수 없으면 전체 파일명을 표시하며 재생을 거부하지 않습니다. 제목 해석 함수는 주입 가능하므로 추후 JSON 메타데이터 제공자로 교체할 수 있습니다. 이번 버전에는 수동 메타데이터 파일을 요구하지 않습니다.

## 예외 처리

일반 또는 배틀 목록이 비면 해당 상황에서 조용히 대기합니다. 배틀 폴더가 비었다고 일반 음악을 임의로 대신 틀지는 않습니다. 이동·삭제·손상·디코딩 실패는 로그를 남기고 다음 사용 가능한 곡을 고릅니다. 모든 곡이 실패하면 같은 파일을 무한 재시도하지 않고 대기합니다. 파일 상태가 바뀌거나 앱을 다시 실행하면 다시 검토합니다. 앱 오류 로그는 기존 `data/idol_manager.log`를 사용합니다.

장치나 Qt Multimedia가 없으면 음악 상태에 이유를 표시하고 게임 핵심 기능은 계속 실행합니다. 출력 장치가 다시 연결되면 재시도할 수 있습니다. 설정 파일이 잘못되면 기본값을 사용하고, 저장 실패도 게임을 종료시키지 않습니다.

## 테스트와 Windows 재생 확인

```powershell
$env:QT_QPA_PLATFORM = 'windows'
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe tools/verify_bgm_playback.py
```

최종 회귀 결과는 **199개 실행: 197개 통과, 2개 조건부 건너뜀(103.013초)**입니다. 건너뛴 두 항목은 이미 진행된 실제 세이브가 최초 미편성 상태라고 가정하는 과거 복사본 테스트입니다. BGM 테스트는 모두 실행했습니다. 초기 상태·복구·편성 자체의 임시 DB 테스트와 기존 경기 규칙 회귀 테스트는 통과했습니다.

카테고리별 탐색, 1,200곡 목록, 셔플 순환·경계 중복 방지, 곡 종료, 빈 폴더, 손상 파일, 삭제·추가 파일 갱신, 장치/백엔드 부재, 빠른 전환·페이드 취소, 일시정지 상태 전환, 0/100% 볼륨·음소거·설정 저장, 알림 1.5초+0.3초 자동 종료를 검증했습니다. 실제 경기 판정 뒤 관전 탭에서만 배틀 음악으로 바뀌며, BGM 상태를 바꿔도 저장된 판정 결과와 복사본 DB가 변하지 않는 것을 확인했습니다.

Windows 10 / Python 3.13.3 / Qt 6.12.0에서 실제 프로젝트 MP3의 DEFAULT·BATTLE 재생을 확인했습니다. `스피커(iFi USB Audio SE UAC1)` 장치로 출력하도록 연결된 `QAudioOutput`, 재생 상태, 약 0.9초 이상 위치 증가, 유효한 PCM 디코딩 버퍼를 기록했습니다. 실제 손상 MP3를 건너뛰고 한글 경로 WAV를 재생·반복하는 별도 시험도 통과했습니다. WAV 시험은 새로 생성한 임시 무음 PCM과 볼륨 0으로 디코딩·반복을 검증한 것입니다. **사람이 직접 소리를 청취한 확인은 하지 않았습니다.** 다른 PC와 다른 오디오 장치는 별도 검증이 필요합니다.

진단은 임시 게임 DB와 임시 음악 설정으로 수행합니다. 진단 자체도 복사본 전체 DB 행이 전후 일치함을 검사합니다. 기록은 `.test-artifacts/bgm_native_playback.json`, `bgm_native_playback.log`, `bgm_native_wav_tests.log`, `bgm_native_default.png`, `bgm_native_battle.png`, `bgm_full_tests.log`에 있습니다.

## 기존 게임 보존

BGM 코드에는 SQLite 연결·변경 API가 없고 게임 서비스와 분리되어 있습니다. DB 스키마·드래프트·선수 능력치·기획사 자금·일정·선수단/날짜 복구 로직·경기 판정 규칙은 변경하지 않았습니다. 원본 음악을 삭제·다운로드·변환하지 않았습니다.

작업 중 원본 세이브가 외부 실행에서 계속 진행되는 것이 관측됐습니다. 시작 시 `absolute_day=3`이었고 이후 `absolute_day=7`과 경기·선수단·리더 기록 변경이 확인됐습니다. 이 진행 내용을 이전 스냅샷으로 덮어쓰거나 되돌리지 않았습니다. 따라서 원본 전체가 작업 시작 해시와 같다고 보고하지 않습니다. BGM 조작 전후 전체 행 동일성은 격리한 복사본으로 검증하고, 원본은 읽기 전용 검사 결과와 변화 목록을 감사 파일에 남깁니다. 원본 음악·사진·설정과 핵심 보존 항목의 최종 대조는 `.test-artifacts/bgm_verification.json`에 기록합니다.

최종 읽기 전용 대조 시에는 원본이 `absolute_day=20`까지 진행돼 있었습니다. 이 진행은 그대로 보존했고, 사진·로고·음악을 포함한 기존 자산 351개와 두 게임 설정 파일은 시작 시 해시와 모두 일치했습니다. 이름·능력치·잠재력·기획사 자금·드래프트·시즌 일정 규칙·대진 연결도 시작 시 행 데이터 해시와 일치했습니다. DB 버전은 6이며 무결성·외래 키 검사도 정상입니다. 실제 오디오 진단용 복사본에서는 BGM 재생 전후 전체 DB 행이 완전히 일치했습니다.
