## PART B — 확정한 규칙과 구현

최신 `IDOL_Manager_통합_마스터_기획서_2026-10-27.txt` 10장 및 이번 사용자 추가 답변을 적용했습니다. 처음 요청서의 **2군 일일 성장은 폐기**하며, 1군·2군·연습생 모두 **직전 월~일 활동을 다음 월요일에 주 1회 정산**합니다. 일일 확률 환산이나 매일 능력치 지급은 없습니다.

### 1군

- 실제 1군 출전의 주요 판정 성공 횟수 상위 2개 능력치를 선택합니다. 동률은 저장된 난수 시드로 무작위 처리합니다.
- 1위 상승 확률 `min(100,(100-A)×3)%`, 2위 `min(100,(100-A)×2)%`, 성공 시 각각 +1.
- 위 2개를 제외한 능력치 중 일반 판정 시도가 적은 2개를 골라 각각 `A%`, `A/2%` 확률로 -1.
- 해당 주 부상 또는 연속 출전 3일째 도달 기록이 있으면 위 기본 상승 2회만 제외하며, 감소·독립적인 PA 격차 추가 성장은 유지합니다.
- 실제 무출전이면 서로 다른 2개 능력치가 -1. 단, 포스트시즌 대진이 없는 부전승·대기 주에는 이 무출전 감소를 적용하지 않습니다.

정규·특별전·포스트시즌의 **실제 main/support 판정만** 집계합니다. 정규 동률 결정전, 데스매치, 리더 추가 판정, 몰수 가상 결과는 제외합니다. 특별전은 저장된 30회/60회 등 실제 판정 수를 그대로 사용합니다. 2군으로 특별전에 출전한 기록은 1군 출전으로 계산하지 않습니다. 더블헤더 경기 수와 출전 날짜 수는 별도로 집계합니다.

### 2군·연습생·리더

2군은 주 1회 서로 다른 능력치 2개에 독립적인 상승 `(100-A)×2%`와 하락 `A/2%` 판정을 수행합니다. 상승만 성공 +1, 하락만 성공 -1, 둘 다 성공 또는 둘 다 실패는 0입니다. 상쇄를 먼저 계산한 뒤 0~개별 PA로 제한합니다.

연습생은 주 1회 서로 다른 능력치 4개에 `(100-A)×1.5%`로 +1을 판정하며 일반 훈련 감소는 없습니다. 자동 프로 데뷔·2군 승격·새 계약을 만들지 않습니다.

지난 일요일의 실제 2군 리더는 현재 리더십/2% 확률로 같은 기획사의 2군 선수(자신 포함) 1명에게 성장 가능한 무작위 능력치 +1을 부여합니다. 기본 성장 유형과 별개인 기존 리더 보너스입니다.

선택적 집중 훈련의 기본 2%, 기존 코치 힌트가 있는 경우 3.5% 수식은 순수 계산 모듈에 준비했습니다. 현재 코드에는 유료 훈련 선택·코치 힌트·훈련비 정산 기능이 없으므로 **임의로 활성화하거나 무료 훈련·새 과금을 만들지 않았습니다.** 이번 단계에 새 시설·코치 체계·재정 정산 UI를 추가하지 않습니다.

### 공통 추가 성장과 PA

기본 성장·2군 리더 보너스 이후 `D = 평균 PA - 평균 CA`로 다음 확률을 정하고 주 2회 독립 판정합니다.

| D | 판정당 확률 |
|---|---:|
| 30 이상 | 50% |
| 20 이상 30 미만 | 40% |
| 10 초과 20 미만 | 25% |
| 0 초과 10 이하 | 10% |
| 0 이하 | 0% |

성공 시 개별 PA 미달 능력치 하나를 균등 선택하여 +1합니다. 두 판정이 같은 능력치를 선택할 수 있으며, 상한에 도달하면 다음 선택에서 제외합니다. 나이 보정·AI 보너스·플레이어 페널티는 없습니다.

모든 증감은 0~100 및 **각 능력치의 개별 PA**를 지킵니다. PA 자체는 갱신하지 않습니다. 실제 CA가 변한 경우에만 저장값과 평균을 갱신하며, 무변화 노화 판정으로 기존 평균 캐시를 불필요하게 덮어쓰지 않습니다.

## 일별 소속과 월요일 처리 순서

날짜를 마칠 때 `development_days`에 실제 신분·기획사·리더 상태를 한 번 기록합니다. 같은 날 재조회나 주말의 최종 소속으로 과거 행을 덮어쓰지 않습니다. 월~일 7일 중 최다 소속 일수로 기본 성장 유형을 정하고, 동률은 **1군 → 2군 → 연습생** 순서입니다. 기본 성장은 1명당 주 1회이고 PA 격차 추가 성장도 별도로 주 2회만 수행합니다.

날짜 진행 트랜잭션의 순서는 다음과 같습니다.

1. 현재 날짜의 모든 경기·특별전·결정전 완료 확인.
2. 기존 일일 피로·부상 처리와 당일 소속 기록 저장.
3. 다음 날이 월요일이면 직전 주 기본 성장 → 2군 리더 보너스 → PA 격차 추가 성장.
4. 누적 주기에 해당하는 능력치 노화 감소, 해당 시점의 시즌 나이 증가.
5. 정규 마지막 주이면 갱신된 CA와 종료 시점 선수단으로 동률 결정전 준비.
6. 기존 월요일 부상 강등·회복·선수단 운영 및 다음 날짜 저장.

성장 정산 전 과거 출전·피로·부상 기록을 삭제하지 않습니다. 이전에 완료한 경기의 입력·난수·점수·개인 기록은 당시 데이터로 유지하고 새 경기만 새 CA를 사용합니다.

포스트시즌에도 확정한 성장·노화를 적용합니다. 비시즌은 성장할 활동 주간이 아니므로 훈련·성장·노화 감소를 쉬며, **비시즌 첫 월요일에는 직전 포스트시즌 마지막 주의 마감 성장만 처리**합니다. 이후 비시즌 4주의 활동으로 새 성장 보상을 만들지 않습니다.

## 노화 감소와 나이 증가의 구분

능력치 노화 감소는 기획서의 첫 판정인 **정규 2주차 월요일(누적 7일)**을 최초 기준으로 **14일 간격**입니다. 27세 이하는 감소 없음, 28~29세는 무작위 1개 -1, 30세 이상은 서로 다른 2개 -1입니다. 0 아래로 내려가지 않습니다.

31주 시즌 경계에서 주기를 초기화하지 않습니다. 예를 들어 누적 217일은 시즌 2 정규 1주 월요일이지만 이어진 주기에 해당하므로 판정합니다. 비시즌에 도달한 판정은 건너뛰며 주기 자체는 그대로 유지합니다.

가상 **나이는 2주마다 증가하지 않습니다.** 비시즌 1주 월요일에 기존 인물 전체가 시즌당 한 번 +1세가 됩니다. 내부적으로 미등장·미지명 인물도 나이를 먹지만, 이들의 정확한 CA·사진·이름을 정산 UI로 우회 공개하지 않습니다.

정산 순서와 수치는 `config/development.json`에 분리하고 세이브의 정산 런타임에 규칙을 저장합니다. 이미 적용한 기록을 재조회하거나 설정 파일을 바꿨다는 이유로 재추첨하지 않습니다.

## 저장과 기존 세이브

DB 버전은 **11**, 추가 테이블은 다음과 같습니다.

| 테이블 | 목적 |
|---|---|
| `development_runtime` | 적용 시작일·독립 난수 시드·적용 규칙 |
| `development_days` | 날짜별 실제 소속·기획사·리더 사실 |
| `development_settlements` | 종류/월요일별 유일한 완료 정산 |
| `development_results` | 인물별 CA·나이 전후, 변화량, 적용 신분, 제외 사유, 활동 집계 |
| `development_trials` | 비공개 판정 확률·주사위·효과 기록 |

하나의 주간/노화/나이 처리와 날짜 진행을 SQLite 트랜잭션으로 묶습니다. 실패·강제 종료 시 부분 선수 갱신·정산 기록·날짜 이동이 함께 롤백됩니다. 동일 월요일/유형 유일 키 및 쓰기 잠금으로 중복·동시 적용을 차단합니다. 공개 기록 조회는 정산을 호출하지 않고 PA나 비공개 판정 테이블도 읽지 않습니다.

마이그레이션은 백업 후 테이블과 설정만 추가하며 **CA·PA·나이·원래 경기 기록을 즉시 변경하지 않습니다.** 현재 주의 소속은 기존 기록으로 입증되는 날짜만 보완합니다. 알 수 없는 과거 소속은 만들어내지 않고 부분 이력으로 표시합니다. 적용 시작 전 이미 끝난 주의 성장·노화를 소급 지급하지 않습니다.

드래프트 추정 범위는 초기 공개 자료로 그대로 유지합니다. 지명된 선수의 현재 CA가 성장한 뒤 초기 추정 범위와 달라질 수 있어도 다시 추첨하지 않습니다. 미등장·미지명 인물의 정산 내부 행은 공개 UI에서 제외합니다.
