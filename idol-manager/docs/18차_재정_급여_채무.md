# 18차 기획사 재정 · 급여 · 채무 개발 보고

마스터 기획서 14장과 18차 요청서를 기준으로 구현했습니다. 이번 업데이트는 회계와 조회 UI이며 경기·피로·부상·성장 확률 및 217일 시즌 규칙을 변경하지 않습니다.

## 실행과 화면

실행 중인 게임을 완전히 종료하고 프로젝트의 `실행하기.bat`으로 다시 실행합니다. 왼쪽 **기획사 재정** 메뉴에서 10개 기획사를 선택합니다.

- 예산 전망: 현금·채무·순자금, 이번 주/시즌 실제 현금 수입·지출, 다음 급여 회차·기본 예상액, 운영비, 시즌 종료 예상 순자금, 거래순 현금 그래프, 앞으로 마감할 4주 예산.
- 거래 장부: 날짜, 정산 주차, 종류, 금액·조정액, 현금·채무 변동, 거래 전후 현금, 관련 선수, 정산 ID, 설명.
- 계약·급여 명세: 사진, 이름, 현재 선수단, 연봉, 회계 적용일, 당시 연봉, 기본 급여, 실제 1군 활동 주/2군 소속 주, 보너스·감액, 최종 의무, 지급 누계와 미지급. 이름을 클릭하면 기존 공통 프로필을 엽니다.
- 채무 기록: 최초 금액·잔액·상환 누계와 관련 급여 명세.
- 강제 매각 검토: 연봉 내림차순 후보, 연봉의 절반 가격, 자금·정원을 충족한 구매 가능 기획사, 거래 미구현 안내.

새 표들도 기존 도킹 시스템을 사용합니다. 선수 계약과 급여 명세는 별도 탭을 넓게 사용합니다. 제목줄로 분리하거나 열 경계를 직접 조절할 수 있습니다. 조회와 새로고침, 프로필 열기는 정산을 실행하지 않습니다. 다른 기획사 현금을 수정하는 UI는 없습니다.

## 1. 구현 전 상태와 수정 파일

DB 11에는 `agencies.funds_krw`만 있고 계약·연봉 테이블, 재정 원장, 안전한 계약 승계/이적 서비스, 집중 훈련 선택 기능은 없었습니다. 일별 `development_days`, 정규/특별전 출전 기록, 월요일 성장 정산과 포스트시즌 마감 훅을 재사용했습니다.

추가:

- `config/finance.json`: 게임 생성·회계 도입 시 고정 저장할 회계 규칙.
- `idol_manager/finance_schema.py`: DB 12 스키마.
- `idol_manager/finance_service.py`: 회계·급여·채무·조회·자금 검증.
- `idol_manager/finance_policy.py`: 공개 현금 정보만 사용하는 AI 예산 여유 정책.
- `idol_manager/ui/finance_page.py`: 대시보드, 그래프, 장부·명세·채무·매각 검토.
- `tests/test_finance.py`, `test_finance_migration.py`, `test_finance_ui.py`.
- `tools/verify_finance_ui.py`, `verify_finance_seasons.py`, `verify_finance_integration.py`, `verify_finance_preservation.py`.

수정:

- `migrations.py`, `database.py`, `service.py`: 백업 마이그레이션·신규 게임 초기화·서비스 연결.
- `calendar_service.py`: 기존 날짜 트랜잭션에서 주 마감 회계 실행.

- `initial_setup.py`: 새 회계 테이블 인식, 실제 재정 정산 후 날짜 복구 차단. 기존 복구 조건을 완화하지 않습니다.
- 기존 회귀 테스트·마이그레이션 fixture와 시즌 검증 도구: 자금 무변동 가정 대신 원장 대조 및 회계 테이블 보존 검사.
- `README.md`, 이 문서.

## 2. DB 구조와 저장 안전성

DB 버전 **12**, 기존 테이블의 열·데이터는 바꾸지 않는 추가 마이그레이션입니다.

| 테이블 | 책임 |
|---|---|
| finance_runtime | 도입 일수, 당시 확정 규칙 JSON, 이미 종료한 시즌 |
| finance_contracts | 선수·기획사, 프로/드래프트 연습생/자유계약 연습생, 실제 적용 연봉·시작/종료일·근거 |
| finance_settlements | 기획사·시즌·주차·종류별 고유 정산 키 |
| finance_ledger | 수입, 현금 지급, 급여 의무·조정, 미지급·상환 원장 |
| finance_payroll | 계약·시즌·급여 회차별 명세와 지급 누계 |
| finance_debts | 미지급 의무의 최초 금액과 잔액, 관련 급여 |
| finance_points | 기획사 지급 회차별 -2점 페널티 |

현금은 기존 `agencies.funds_krw`가 유일한 원본입니다. 채무는 별도 합계이며 현금 음수와 대출을 만들지 않습니다. 원장은 UPDATE를 차단하고 계약 조건은 기존 행을 다시 쓰지 못하게 하며 계약 기간 중첩도 차단합니다. 향후 계약 변경은 이전 계약을 정상 종료하고 새로운 유효 계약을 추가해야 합니다.

`BEGIN IMMEDIATE`와 고유 정산 키로 날짜·성장·회계가 함께 확정됩니다. 기획사 처리 중 오류가 나면 그 날짜의 모든 변경이 롤백됩니다. 동시 요청은 직렬화하며 동일 회차는 재실행하지 않습니다. 원장을 조회해 돈을 지급하는 API는 없습니다.

## 3. 시작 자금과 주간 후원금

신규 게임은 기존 초기화의 기획사별 10억 원을 사용하고 원장에는 최초 자금 사실만 등록합니다. 별도로 10억을 더하지 않습니다.

정규 시즌 각 주 일요일을 마치고 다음 날로 진행할 때 지난 주를 정산합니다. 원장 날짜와 정산 주차는 마감한 일요일/정규 주차입니다. 따라서 24주 급여는 정규 24주 마감에 한 번 기록되며, 포스트시즌 급여가 되지 않습니다.

순서: 주간 후원금 1,000만 원 → 오래된 확정 채무 우선 상환 → 운영비 → 4주 급여. 정규 24주 합계는 기획사별 2억 4,000만 원. 포스트시즌·비시즌 후원금이나 승리 상금은 없습니다.

## 4. 급여·활동·반올림

정규 4·8·12·16·20·24주 마감에 해당 4주를 정산합니다. 기본 급여는 계약 연봉 ÷ 6이며 정수 연산으로 만 원 단위 사사오입합니다. 6회차는 연봉에서 앞선 5회분의 기본 배정액을 뺀 금액으로 오차를 보정합니다. 미지급 상환과 활동 조정은 기본 급여 반올림과 별개입니다.

기존 DB에는 연봉이 없었습니다. 기획서가 확정한 **프로 첫 연봉 3,000만 원**을 회계 도입 시점부터 적용하는 계약을 만들고 기존 선수 데이터는 바꾸지 않습니다. 신규 드래프트 선수도 같은 기준입니다. 계약 기간·협상 결과를 임의 생성하지 않으며, 만료는 미정으로 표시합니다.

1군 활동은 정규 경기 개인 출전 기록 및 특별전의 저장된 실제 1군 출전 기록으로 주당 한 번 셉니다. 미출전 등록, 몰수 가상 점수, 2군 특별전 출전은 1군 활동이 아닙니다. 포스트시즌 출전으로 정규 급여 회차를 만들지 않습니다.

사용자 확정: 2군 주차는 일별 소속 중 최다 신분으로 판정하고 동률이면 1군→2군→연습생. 실제 1군 활동 3주 이상이면 기본 급여 +10%, 2군 소속 3주 이상이면 -10%. 둘 다 충족하면 별도 명세에 남기고 상쇄합니다. 부상 자체로 이미 얻은 활동 보너스를 취소하지 않습니다.

계약이 기간 중 변경된 경우의 일할 계산 규칙은 기존에 없습니다. 완전한 4주에 적용된 프로 계약만 자동 정산하고 기간 중 변동은 장부에 `기간 중 계약 확인 필요`로 남깁니다. 임의로 일할 계산하거나 이전 연봉으로 소급 갱신하지 않습니다. 실제 이적/계약 변경 기능은 19차 범위입니다.

## 5. 운영비와 연습생

정규 각 주의 일별 소속 기록에서 실제 관리·훈련 대상이었던 연습생/2군을 확인합니다. 해당 항목마다 선수별 주 1회 10만 원입니다. 주중 일부라도 해당 역할에 속했던 경우 해당 서비스를 관리한 주로 계산하며, 일당으로 반복 부과하지 않습니다. 서로 다른 역할의 실제 서비스는 별도 항목입니다. 성장의 확률·대상 선정 방식은 바꾸지 않습니다.

연습생의 계약 유형은 구분해 보존합니다. 드래프트 출신 연습생의 연 1,000만 원과 자유계약 연습생의 연 0원은 계약에 기록하되, 드래프트 연습생 급여의 지급 시점은 미정이므로 자동 지급·채무를 임의 생성하지 않습니다. 관리비와 연봉을 합치지 않습니다.

**집중 훈련 선택·코치 힌트는 기존에 미구현**이므로 이번에도 성장 효과를 임의로 추가하지 않았습니다. 집중 훈련 미선택자에게 추가 15만 원을 청구하지 않습니다. 비용 설정과 공통 자금 검증은 준비했지만 실제 선택·비용 부과는 미구현입니다.

포스트시즌의 별도 훈련비·관리비는 규칙이 미정이므로 부과하지 않습니다. 기존 포스트시즌 성장 정산은 유지합니다. 비시즌 4주에도 반복 운영비가 없습니다.

## 6. 시즌 마감 보너스

포스트시즌 결승 시리즈 우승 확정과 같은 트랜잭션 안에서 모든 기획사에 10억 원씩 한 번 지급합니다. 성적별 차등과 별도 우승 상금은 없습니다. 비시즌 진입 훅도 같은 고유 키를 사용하므로 중복 지급하지 않습니다. 회계 도입 전에 종료된 시즌은 보너스를 소급 지급하지 않습니다.

## 7~8. 채무와 승점

현금으로 지급할 수 있는 금액만 실제 출금하고 나머지는 채무로 남깁니다. 운영비 부족분도 의무를 없애지 않고 별도 운영 채무로 남기며, 급여 페널티와 구분합니다.

급여 미지급은 **기획사별 4주 지급 회차당 -2점 한 번**입니다. 선수 수나 미지급액에 곱하지 않습니다. 과거 채무를 보유한 이유만으로 다음 주에 다시 차감하지 않습니다. 다음 지급 회차에서 새 미지급이 생기면 그 회차에 -2점이 새로 기록됩니다.

정규 경기 승패와 원래 +1점 기록을 수정하지 않고 별도 페널티 원장을 순위에 합산합니다. 포스트시즌에서 이미 확정한 최종 순위·시드는 바꾸지 않습니다.

수입은 먼저 오래된 채무부터 상환합니다. 급여 채무가 상환되면 해당 선수 지급 누계도 갱신합니다. 현금 변동과 채무 변동을 모두 남깁니다. 급여 감액은 현금 수입이 아니며, 기본/보너스 의무와 실제 지급 행을 이중 지출로 집계하지 않습니다. 대시보드 총수입·지출은 실제 현금 흐름 기준이고 채무 상환은 현금 지출에 포함됩니다.

## 9~10. 매각 제한과 AI

안전한 이적·계약 승계 서비스가 없어 **실제 강제 매각은 수행하지 않습니다**. 채무가 있으면 검토 후보를 연봉 순으로 보여주고 가격과 구매자 현금·채무·프로 정원 16명 및 1군/2군 자리를 확인합니다. 구매 가능 팀이 있어도 소유권·계약·현금 이동을 가짜로 처리하지 않습니다. 구매자가 없으면 채무가 유지됩니다.

모든 10개 기획사에 같은 회계 루프를 적용합니다. AI 보너스·면제·숨겨진 PA 조회는 없습니다. `FinanceService.validate_spend()`는 채무나 현금 부족 시 재량 지출을 거절하며, 향후 계약 서비스가 같은 쓰기 트랜잭션의 connection으로 호출할 수 있습니다.

`budget(agency, style)`는 다음 기본 급여와 운영비 예비금을 빼서 지출 여유를 반환합니다. 안정형 4주·균형형 2주·공격형 1주 예비금의 차이만 있고 수입·급여·채무·페널티는 동일합니다. 현재 새로운 영입·집중 훈련 행동이 없어 AI가 이 예산으로 자동 구매하는 기능은 추가하지 않았습니다.

## 11~12. 예산 전망·급여 이력

예산은 현재 계약·소속 유지 가정입니다. 향후 활동 보너스/감액, 미정 계약 변경, 미구현 집중 훈련과 연습생 급여 시점은 넣지 않습니다. 따라서 예상액은 확정 지급액이 아닙니다. 순자금 전망은 음수일 수 있지만 실제 현금은 음수가 되지 않습니다.

프로필 계약 탭에서도 적용 중인 연봉과 저장된 급여 회차·의무·보너스·감액·지급·미지급을 조회합니다. 과거 FA 계약이 남아 있어도 이를 현재 소속 계약으로 표시하지 않습니다.
