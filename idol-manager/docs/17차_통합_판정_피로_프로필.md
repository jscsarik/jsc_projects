# 17차 통합 — 전체 8개 무작위 판정·피로/부상 분석

기존 17차 공통 프로필을 확장했습니다. 정규 경기의 기타 30회 선택 풀 변경과 그 실제 기록의 집계가 이번 통합본의 추가 사항입니다. 정규 24주·포스트시즌 3주·비시즌 4주, 585경기 및 특별전 6회, 승패·리더·데스매치·피로·부상 확률·드래프트·계약·BGM 규칙은 유지합니다.

## 개발 전 확인과 백업

실제 DB는 **버전 11**, 누적 14일, 정규 완료 55건이었습니다. SQLite 온라인 백업:

`data/backups/idol_manager_before_integrated17_20261028_125245_878021_KST.sqlite3`

검증은 복사본·임시 게임에서 수행했습니다. 기존 마스터의 정규 ‘주요 능력치 제외’ 문구는 이번 요청의 **신규 정규/일반 경기**에 한하여 대체합니다. 특별전은 기존 규칙을 유지합니다. 기존 콘텐츠의 주요 능력치 2종/3종과 출전 인원은 바꾸지 않았습니다.

조사 결과 정규와 특별전이 `judgments.basic_trials()`를 공유하고 있었습니다. 따라서 공유 함수의 기본값을 무조건 바꾸지 않고 호출자가 새 풀을 명시하도록 분리했습니다. 기존 공통 프로필·사진 캐시·조건/부상 함수·주간 정산·결과 저장 구조를 재사용합니다.

## A. 무작위 판정 및 저장

- 정규 기본 60회: 주요 그룹 30회, 전체 8개 무작위 그룹 30회
- 주요 30회는 기존처럼 2종 각 15회 또는 3종 각 10회
- 무작위는 매회 `rng.choice(SKILLS)`로 독립·복원 추첨. 주요 능력치·연속 중복도 허용
- 능력치별 등장 횟수를 강제로 맞추지 않음
- 선택된 능력치로 성공 판정을 한 번만 실행. 성공 시 점수도 한 번만 반영
- 출전한 리더 추가 2회, 동점 대표 10회 반복, 피로에 따른 기존 확률은 그대로 사용
- 특별전 5자 30회와 후속 4자 60회는 **주요 제외 무작위 풀 그대로**
- 포스트시즌과 정규 동률 결정전의 신규 일반 60회에는 전체 8개 적용. 결정전은 기존처럼 성장·출전 피로 집계와 구분

AI 선발·휴식·로스터 정책은 수정하지 않았습니다. 새 풀에 맞춘 AI 평가식 재조정이나 전략 개선은 이번 범위에 넣지 않았습니다.

### 완료·준비 경기 보호

| 구분 | 처리 |
|---|---|
| 완료 경기 | 저장된 결과/이벤트를 읽음. 날짜가 달라도 재계산·재추첨하지 않음 |
| 구형 준비 정규 경기 | `engine_version=regular-1`을 인식해 기존 주요 제외 규칙으로 재개 |
| 신규 정규 경기 | `regular-2-all8` 버전으로 준비·저장 |
| 구형 준비 결정전/포스트시즌 | 저장 입력에 새 표식이 없으면 기존 풀로 재개 |
| 신규 결정전/포스트시즌 | 기존 `input_json`에 `regular_random_pool=all8-v2`를 한 번 저장 |
| 특별전 | 기존 `special-1` 경로·풀 유지 |

스키마·테이블·이벤트 중복 필드는 추가하지 않았으며 **DB 11 유지**입니다. 이벤트의 `phase=main/support`는 주요/무작위 그룹, `skill`은 실제 판정 능력치, `probability`는 피로 등이 반영된 성공 확률입니다. 유효 능력치는 `probability×100`, 성공 점수는 기존 `success` 값으로 대응합니다. 무작위 그룹에서 주요 능력치가 나와도 `support` 그룹·해당 실제 능력치로 저장합니다.

## B. 성장 및 개인 통계

주요·무작위 그룹별 기록은 분리하면서, 능력치별 일반 합계는 두 그룹을 더합니다. 프로필 **경기 기록 → 능력치별 일반 합계**에서 주요 시도·무작위 시도·합계·성공·실패·성공률을 조회합니다. 합계는 저장된 이벤트 기준이며 현재 CA로 역산하지 않습니다.

통합 요청의 ‘그룹 관계없이 실제 능력치별 일반 성공 집계’를 적용해, 앞으로 실행하는 1군 주간 정산의 상승 대상 상위 2개도 **주요+무작위 일반 성공 합계**로 선정합니다. 확률·판정 횟수·하락·PA 상한·추가 성장·비시즌 휴식은 바꾸지 않습니다. 기존 `main_successes`와 새 `basic_successes`를 구분해 저장된 사실을 설명하고, 새 성장 정산 버전에는 `all-general-success-v2` 표식을 남깁니다. 기존 완료 정산은 중복 키 검사로 그대로 유지합니다.

후속 사용자 답변으로 위 집계 기준을 명시적으로 확정했습니다. 1위는 `min(100, (100-A)×3)%`, 2위는 `min(100, (100-A)×2)%`이며, 주요 능력치가 무작위 그룹에 다시 나와 성공한 경우도 해당 이벤트의 성공을 한 번만 더합니다. 하락 대상은 기존처럼 상승 대상 2개를 제외하고 일반 시도 횟수가 가장 적은 2개입니다. 실제 30+30 기록 예제에서 랩 9회·보컬 8회가 1·2위가 되는지, 60/40% 상승 확률, 부상/피로 취소, 0·100 경계의 확률 제한을 추가 회귀 시험으로 검증합니다. 기존 원장이나 세이브를 소급 수정하지 않습니다.

후속 확정 검증은 **41개 모두 통과(19.662초)**했습니다. 기존 동작과 일치하여 생산 코드 재변경은 없고, `tests/test_development.py`에 명시적 상위 2개 선정·확률 회귀를 추가했습니다. 로그: `.test-artifacts/integrated17_confirmed_growth_tests.log`. 아래 통합 전체 358개 결과는 이 추가 시험 전의 기록입니다.

정규·특별전·포스트시즌의 실제 일반 판정만 기존 소속 규칙에 따라 집계합니다. 특별전은 실제 30/60회 및 저장된 당시 1군 여부를 따릅니다. 2군 특별전 출전, 결정전, 리더 추가, 데스매치·몰수 가상 판정은 1군 성장 집계에 추가하지 않습니다. 주간 적용 신분이 2군/연습생이면 그 주의 1군 출전 기록을 기본 1군 성장에 중복 반영하지 않습니다.

프로필은 **성장 정산 반영 시도 / 미정산 시도**를 구분하며 이미 끝난 주와 아직 정산 전인 주를 혼동하지 않습니다. 과거에 끝난 경기·순위·정산을 새 규칙으로 다시 만들지 않습니다.

## C. 공통 프로필 확장

공통 `ProfileDialog`/`ProfilePanel`을 재사용합니다. 현재 순서:

**종합 / 능력치 / 피로·부상 / 경기 기록 / 성장 이력 / 계약·경력**

우리·다른 기획사 선수, 1/2군·연습생, 드래프트 후보·지명 이력, 출전자, 정규/특별전/포스트시즌 결과, 사진 대결 카드, 성장 결과, 통합 검색에서 기존 ID 기반 클릭 연결을 유지합니다. 신규 신인 드래프트·계약 협상 전용 화면처럼 아직 없는 화면은 만들지 않습니다.

### 공개와 비공개

- 현재 소속·지명·과거 프로/소속/출전 이력으로 공개 여부 판단
- 공개 선수의 현재 8개 능력치·건강과 산술평균 CA 표시. 건강은 CA에 포함하지 않음
- 과거 공개된 FA는 정확한 능력치 유지
- 미공개 후보는 저장된 13차 5칸 범위·추정 CA만 표시. 조회 시 재생성하지 않음
- 후보의 실제 CA·건강을 조회하지 않는 SQL 경로를 분리
- PA, 남은 정확한 성장량, 유망주 표식, 미래 성장 난수·확률은 미노출
- 성장 이력은 실제 적용된 공개 증감만 표시. 상한 때문에 적용되지 않은 시도는 전달하지 않음
- 이름 대신 ID로 연결하여 동명이인·정렬 후에도 정확한 사람을 열람

능력치 탭에 최근 상승·하락, 저장된 시즌 정산 누계를 추가했습니다. 도입 전 시즌 시작 CA 스냅샷이 없으면 `기록 없음`이며 임의의 과거 CA를 만들지 않습니다. 계약 연봉·기간·시장가치 등 실제 저장 항목이 없는 정보도 `기록 없음`으로 표시합니다.

### 피로와 다음 일정

실제 연속 출전 기록의 피로, **현재 날짜 경기 출전 시의 유효 능력치**, 확인된 다음 팀 일정의 조건부 피로를 구분합니다. 다음 일정 사이에 실제 기록상 공백이 있으면 연속 단계를 무조건 증가시키지 않습니다. 다음 일정이 없으면 수치를 단정하지 않습니다. 현재 부상/선발 미확정 상태에서는 조건부 예측임을 명시합니다.

최근 최대 7일의 실제 출전 달력, 이번 주 출전 날짜 수, 오늘 출전 여부를 표시합니다. 더블헤더는 날짜 1일이며 미확인 과거 구간은 미출전으로 지어내지 않습니다. 원본 8개 수치와 현재 날짜에 출전할 때의 유효 수치를 나란히 보이며 DB 값을 깎지 않습니다.

### 등록·부상·휴식

기존 `public_condition`, `registration_multiplier`, `injury_probability`, `required_rest_weeks`, `promotion_allowed`, `roster_change_reason`을 재사용합니다. 프로필 전용 위험 공식을 만들지 않습니다.

- 실제 출전 주차와 등록 주차를 분리
- 3주 10배·4주 20배·5주 30배·6주 40배 표시
- 확인된 과거 판정 스냅샷의 등록 최고 기록 표시. 없는 과거는 만들지 않음
- 2군 완료/필요/남은 완전 휴식, 초기화 상태, 현재 이동·맞교환 절차의 복귀 가능 여부
- 부상 회복일과 저장된 1군 복귀 제한일을 구분
- 경기·1군 미출전일·2군 소속일의 기본 확률과 현재 조건부 확률을 분리
- 기존 엔진은 2군에도 아직 초기화되지 않은 등록 단계를 반영할 수 있음. 이 동작을 이번 작업에서 임의로 제거하지 않고 실제 식대로 표시
- 발생 당시 선수단은 판정 종류 또는 특별전의 동결 소속 등 확인 가능한 기록으로만 표시. 당시 기획사 정보가 없으면 기록 없음
- 이번 주 실제 연속 3일 도달·부상 발생과 그에 따른 1군 기본 상승 제한을 표시. 최종 주간 적용 신분 확정 전에는 조건부 안내

건강 80·등록 4주 상태의 경기 **기본 0.2% / 현재 4.0%**, 1군 미출전일 **기본 0.1% / 현재 2.0%**를 자동·Windows 테스트로 확인했습니다. 상태 표시를 위해 회복·휴식·성장을 실행하지 않습니다.

통합 검색에는 기존 이름·소속·신분·부상 필터와 숫자 정렬·2명 비교를 유지하고 **현재 부상 위험 배수 정렬**을 추가했습니다. 후보는 공개 추정값으로만 정렬합니다.

## 검증 결과

무작위 120,000회: 능력치당 기대 15,000회, 실제 **14,824~15,134회**, 카이제곱 **6.4327 / 자유도 7**. 주요 한 종류를 가정한 공통 함수 시험의 총 주요 능력치 평균은 **33.70725회**로 기대 33.75회에 부합합니다. 같은 선수의 이웃 무작위 선택이 같은 경우도 7,245회 관찰했습니다. 단일 주요 예시는 분포 시험용이며 실제 기존 30종 콘텐츠를 수정한 것이 아닙니다.
