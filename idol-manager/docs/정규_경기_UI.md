# 정규 경기 출전자 선택·관전·결과 UI

개발 전 `config/generation.json`, `config/season_schedule.json`의 존재와 설정 로더 검증을 확인했습니다. 두 파일 모두 정상이며 복원·변경하지 않았습니다. 기존 Windows 테스트 162개가 62.605초에 통과한 뒤 UI 구현을 시작했습니다.

## 사용 순서

1. 기존 `실행하기.bat`로 실행합니다. 드래프트·최초 편성·플레이어 양군 리더 지정을 먼저 마칩니다.
2. **하루 진행**으로 수요일에 도달한 뒤 사이드바의 **정규 경기**를 엽니다.
3. **오늘 정규 경기** 표에서 플레이어 참가 경기를 선택합니다. 콘텐츠·주요 능력치·양측에 적용되는 필요 출전 인원을 확인합니다.
4. 출전 가능한 1군 중 필요한 인원을 체크합니다. 표의 정렬을 바꿔도 내부 선수 ID로 선택을 관리합니다. 주요 능력치는 굵은 제목으로 표시합니다.
5. **경기 시작**을 누릅니다. 상대의 출전자는 기존 공개 능력치 기반 AI 정책이 선택합니다.
6. 경기 진행 탭에서 점수·선수별 현재 성공 횟수를 관전하거나 **스킵 · 저장된 동일 결과 확인**을 누릅니다.
7. 결과 탭에서 승리·패배 기획사, 정규 점수와 데스매치 점수, 개인 기록·능력치별 기록을 확인합니다. 리그 순위 탭도 갱신됩니다.
8. **AI 경기 빠른 진행**은 현재 진행 가능한 다른 기획사 경기만 기존 엔진으로 처리합니다. AI 경기를 개별 선택해 관전하는 것도 가능합니다.
9. 더블헤더는 해당 날짜의 1차 5경기를 모두 끝낸 뒤 2차 경기를 진행합니다. 플레이어 2차 경기의 출전자도 직접 선택합니다.
10. 당일 정규 경기를 모두 마치면 **하루 진행**을 누를 수 있습니다. 미처리 특별전이 있는 날짜는 기존처럼 차단됩니다.

과거 결과는 목록 위 콤보의 **저장된 경기 결과**에서 선택하고 **저장 결과 보기**를 누릅니다. 날짜를 넘기거나 앱을 종료해도 결과는 남습니다. 해당 버튼은 저장된 결과를 읽기만 합니다.

AI 빠른 진행은 버튼을 누른 시점의 당일 경기 ID에 한정합니다. 다른 창에서 날짜를 바꾸더라도 다음 날 경기까지 이어서 처리하지 않습니다.

## 판정과 재생

`MatchService.play()`는 기존 엔진으로 한 번 계산하고 결과·개인 기록·판정 이벤트를 트랜잭션으로 저장합니다. UI의 작업 스레드가 이 API를 호출하며, 계산·저장 완료 후 메인 Qt 스레드에서 같은 이벤트를 재생합니다. 관전 도중에는 날짜·새 게임·선수단 변경을 잠가 다른 화면 작업과 충돌하지 않도록 했습니다.

- 기본 60틱 × 0.5초 = 약 30초입니다. 출전자별 주요 30회·보조 30회는 기존 엔진 그대로입니다.
- 실제 출전한 1군 리더의 추가 리더십 2회는 60틱에 별도 표시하며 기본 판정 길이에 더하지 않습니다.
- 데스매치는 저장된 대표 판정 10틱씩 약 5초 단위로 이어집니다. 반복 동점이면 기존 엔진이 저장한 묶음도 계속 표시합니다.
- 스킵은 남은 저장 이벤트를 즉시 반영하고 결과 탭을 엽니다. 난수 추첨·판정·기록 누적을 다시 호출하지 않습니다.
- 관전 중 앱을 닫더라도 이미 저장한 결과를 다음 실행에서 확인할 수 있습니다.
- 저장 실패 또는 계산 도중 중단되어 준비 기록만 남으면 **저장된 경기 재개**로 표시합니다. 체크박스를 잠그고 기존 출전자·시드로 재개합니다.
- 엔진이 승자를 정할 수 없어 차단한 경기는 이유를 표시하며 새 결과를 임의 생성하지 않습니다.

개인 기록에는 기본 시도·주요·보조 횟수, 일반 성공·실패, 리더 성공/시도, 데스매치 성공/시도, 일반+리더 기준 전체 성공률과 승리/패배 아이돌 기록이 나옵니다. 능력치별 표에서는 주요·보조·리더 추가·데스매치를 구분합니다. 팀의 `base_score`는 기존 정의대로 리더 추가 성공을 포함한 정규 점수입니다.

순위는 저장된 실제 정규 경기 결과의 승점으로만 표시합니다. 동일 승점은 공동 순위이며 이번 단계에서 동률 결정 규칙이나 결정전을 추가하지 않았습니다.

## 유지한 제한과 데이터 보호

선택 API는 현재 날짜의 플레이어 소속 출전 가능 1군만 전달합니다. 2군·연습생은 표에 들어오지 않으며 엔진도 내부 ID를 다시 검증합니다. 가능 인원이 부족하면 가능한 인원만 선택하고, 0명이면 기존 몰수 규칙을 적용합니다. AI 정책과 출전 가능 여부 정책은 기존 모듈을 그대로 사용합니다. 잠재력·성장 유형·특별 유망주 정보는 UI와 AI에 전달하지 않습니다.

출전 선택과 오늘 경기 조회는 읽기 전용 API입니다. 새 DB 테이블이나 마이그레이션은 없으며 스키마 버전 6과 기존 28주(196일) 날짜 구조를 유지합니다. 결과 저장은 기존 경기 테이블만 사용합니다. 경기로 인한 능력치·건강·잠재력·선수단·기획사 자금 변경도 없습니다.

특별전 자동 완료·스킵, 31주 시즌, 포스트시즌, 정규 동률 결정전, 성장·부상·월요일 성장 정산은 구현하지 않았습니다. 아직 실제 부상 정보가 없으므로 건강 점수 자체로 임의의 출전 금지 기준을 만들지 않았습니다.

## 테스트 실행

```powershell
$env:QT_QPA_PLATFORM = 'windows'
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

새 GUI 테스트에는 실제 0.5초 타이머로 약 30초 관전한 결과와 동일한 DB 복사본의 스킵 결과를 비교하는 시험이 포함됩니다. 관전 중 저장 데이터가 변하지 않고, 두 결과의 전체 판정 이벤트·선수 기록이 동일한지 검사합니다. SQL 권한 검사로 잠재력·성장 유형 열의 읽기를 거부해도 출전자 선택부터 AI 경기·결과 표시까지 통과하는지 확인합니다.

실제 프로젝트 세이브는 읽기 전용으로 조사하고 복사본에서만 날짜 복구·최초 선수단 5명 확정·AI 9곳 편성·양군 리더 지정·첫 수요일 경기·다른 AI 경기·다음 날 진행을 시험합니다. 원본 파일은 자동으로 복구하거나 경기를 진행하지 않습니다.

증거 파일은 `.test-artifacts/match_ui_before.json`, `match_ui_baseline_tests.log`, `match_ui_full_tests.log`, `match_ui_selection.png`, `match_ui_replay.png`, `match_ui_result.png`, `match_ui_verification.json`에 있습니다.

## 최종 검증 결과

Windows 10 / Python 3.13.3 / PySide6 6.12.0의 Qt `windows` 플랫폼에서 **전체 178개 테스트 통과(100.708초)**. 신규 GUI 13개와 순수 재생 3개 테스트를 포함합니다. 실제 500ms 타이머 관전과 스킵의 이벤트·점수·개인 기록 완전 일치, 양군 60회 판정과 리더 추가, 반복 데스매치 분리, 결과 영구 저장·재실행·중단 후 재개, 더블헤더 순서, AI 빠른 진행의 당일 범위, 특별전 차단을 검증했습니다.

실제 세이브의 복사본에서 초기 월요일 복구 → 1군 5명·2군 11명 확정 → AI 9곳 편성 → 플레이어 양군 리더 저장 → 화요일·수요일 진행 → 첫 수요일 플레이어 경기와 당일 AI 경기 완료 → 목요일 진행까지 GUI 통합 테스트를 통과했습니다. 해당 복사본에서도 기존 능력치·잠재력·건강·선수단·리더·드래프트·자금과 대진의 고정 필드는 변하지 않았습니다.

원본 DB 27개 테이블의 전체 행 해시, 원본 사진·로고 320개와 두 설정 파일의 파일 해시가 개발 전과 일치했습니다. 원본은 스키마 6, `absolute_day=2`·수정 버전 3, 드래프트 160명, 정규 일정 585경기, 특별전 6회, 경기 준비·결과 0건 그대로 보존했습니다. 스키마나 시즌 규칙을 변경하지 않았으며 원본에서 경기를 실행하지 않았습니다. SQLite 무결성·외래 키 검사도 통과했습니다.

최종 자산 검사 중 `assets/audio/`에 음원 31개가 추가로 발견됐습니다. 기존 320개 자산은 누락·변경 없이 보존됐고 추가 음원도 수정하지 않았습니다. 오디오 재생 기능은 이번 개발 범위에 포함하지 않았습니다.

다른 Windows PC·Python 3.12·실제 전원 차단 환경은 이번에 검증하지 않았습니다. 게임 도중 프로세스 종료·저장 실패의 원자성은 기존 엔진 테스트와 이번 UI 재개 테스트에서 임시 DB로 검증했습니다.
