# 선수단·선수 시장 가독성 개선

- 아이돌 명단 메뉴를 빼고 아이돌 탐색·분석을 첫 메뉴와 기본 시작 화면으로 변경했습니다. 세로형 화면 선택 목록도 같은 순서입니다.
- 선수단 표에 1군 연속 등록 주차, 필요 휴식 주차, 남은 휴식 주차를 표시합니다. 불필요한 완료 휴식 열은 제거했습니다. 완료 휴식은 내부의 위험 해제 계산에만 사용합니다.
- 2군으로 내려간 직후에도 아직 해제되지 않은 등록 위험 주차는 남아 있을 수 있습니다. 완료 휴식은 기존 엔진이 인정한 완전한 2군 휴식 주입니다. 등록 위험이 이미 해제되었으면 필요한 휴식과 남은 휴식은 0으로 표시합니다. 건강 회복을 뜻하지 않습니다.
- 선수 시장 사진을 46×56, 기본 행 높이를 64 이상으로 키웠습니다. 표 글자는 14px, 능력치는 15px 굵은 글자로 표시합니다.
- 8개 능력치를 한 셀에 나열하던 표시를 보컬·댄스·랩·예능·외모·신체·지성·리더십 각각의 열로 분리했습니다. 평균과 건강도 따로 표시합니다.
- 시장 상단 **선수 표 보기**에서 **능력치·사진 크게**와 **계약·입찰 정보**를 전환합니다. FA·재계약·방출·연습생 표에 적용됩니다. 좁은 화면에서는 기존 정보 페이지/행 페이지를 사용합니다.
- 미지명 후보는 저장된 추정 범위와 추정 평균만 표시하고 건강은 미공개입니다. 능력치 정렬도 공개된 값·범위의 중앙값을 사용합니다. 실제 PA를 읽거나 공개하지 않습니다.
- 지나치게 좁던 시장의 기존 열 배치 대신 새 레이아웃 설정 키를 사용합니다. 이후 직접 조절한 열 크기는 다시 저장됩니다. 다른 화면의 기존 열 설정은 유지합니다.

변경 파일: `idol_manager/squads.py`(읽기 전용 표시 자료), `ui/squad_model.py`, `ui/squad_page.py`, `ui/market_page.py`, `ui/main_window.py`, `ui/portrait_layout.py`, `ui/table_widgets.py`.

검증: `tests/test_ui_readability.py` 2개 및 기존 시장 실제 입찰 버튼 검사 1개 최종 PASS. 숫자/추정 범위 정렬과 Windows 창, 900px 세로형 이동·보기 전환, 후보 비공개, 조회 후 DB 불변을 확인했습니다. 테스트 오류는 해당 항목만 수정·재검사했습니다. 전체 테스트는 반복하지 않았습니다.

## 후속 수정: 휴식 기준과 월요일 변경 제한

- 필요 휴식: 1군 등록 0~2주 0주 / 3주 1주 / 4주 이상 2주입니다. 부상 확률 공식·위험 배수·건강은 그대로입니다. 필요 휴식이 0이더라도 계속 1군에 있는 선수의 등록 카운터가 월요일마다 초기화되지 않도록 했습니다.
- 일반 1군↔2군 이동과 맞교환은 같은 월요일에 선수마다 한 번만 가능합니다. 맞교환한 두 선수 모두 해당됩니다. 다른 선수끼리의 교체는 가능하며, 다음 월요일에는 다시 변경할 수 있습니다. 리더 변경은 이 제한의 대상이 아닙니다.
- 기존 `condition_events`의 실제 manual 이동 이력을 사용해 저장·재실행 뒤에도 제한합니다. `BEGIN IMMEDIATE` 안에서 검사·저장하므로 동시 요청과 거부된 교체는 일부만 반영되지 않습니다. 최초 편성은 횟수에 포함하지 않습니다.
- 부상 자동 교체, 특별전 출전, 기존 포스트시즌 금요일 예외 경로는 그대로입니다. 부상 복귀 제한일 같은 다른 규칙은 해제하지 않습니다.
- UI 버튼과 프로필 복귀 안내에도 오늘 변경 여부를 반영합니다.
- 프로필 피로·부상 탭은 기본 6~8줄로 건강·출전 상태·피로·등록 주차·필요/남은 휴식·복귀 안내를 표시합니다. 확률·과거 날짜·성장 제한 설명은 기본 접힌 **자세히 보기**에 있습니다. 후보의 비공개 정보는 접힌 상세에도 넣지 않습니다.

추가 변경: `idol_manager/condition_rules.py`, `conditions.py`, `profile_condition.py`, `ui/profile_dialog.py` 및 기존 선수단 서비스/화면. DB 스키마 변경이나 기존 선수 상태 재생성은 없습니다.

검증: `tests/test_squad_daily_limit.py` 전용 8개와 Windows UI 관련 2개, 총 10개 최종 PASS. 같은 날 재이동 차단·재시작·다른 조합·다음 월요일·화요일 차단·부상 예외·동시 요청·휴식 0/1/2 경계·부분 휴식·접기/펼치기·후보 비공개를 확인했습니다. 구형 `test_conditions`의 두 검사는 건강 100을 넣는 예전 픽스처가 현재 상한 90 제약과 충돌해 실행되지 않았으며, 해당 두 휴식 사례를 현재 픽스처로 옮겨 검증했습니다. 구형 검사 통과로 계산하지 않았습니다.
