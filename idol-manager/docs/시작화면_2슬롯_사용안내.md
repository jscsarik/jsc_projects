# 시작 화면과 2슬롯 저장 사용 방법

실행 파일: `dist/release_start_menu/IDOL_Manager/IDOL_Manager.exe` (0.29.0).
배포 ZIP: `dist/IDOL_Manager-0.29.0-Windows-x64.zip`.
ZIP은 폴더 전체를 풀어 EXE와 `_internal`을 함께 유지하세요. 소스는 기존 `실행하기.bat`로 실행합니다.

## 기존 게임 이어서 하기

시작 화면 아래 **이전 버전의 게임 저장 파일** 목록에서 원본을 고른 뒤 **슬롯 1로 가져오기** 또는 **슬롯 2로 가져오기**를 누릅니다. 여러 원본이 있으면 직접 선택합니다. 목록에 없으면 **다른 이전 저장 파일 찾기**에서 예전 SQLite 파일을 지정하세요.

원래 `%LOCALAPPDATA%\IDOL_Manager\saves\idol_manager.sqlite3`와 프로젝트의 `data/idol_manager.sqlite3`는 그대로 남습니다. 단순 실행만으로 이 파일을 옮기거나 초기화·마이그레이션하지 않습니다. 선택한 복사본만 필요한 스키마 마이그레이션을 수행합니다.

슬롯을 가져온 뒤 카드의 **이어하기**를 누릅니다. 이후 하단 **이어하기**는 최근 정상 진입한 슬롯을 사용합니다. 플레이 기록이 하나도 없으면 확인된 마지막 정상 저장 시각을 사용하며 파일 수정 시각만으로 판단하지 않습니다. 시각이 같거나 확인 불가이면 작은 슬롯 번호를 우선합니다. 손상된 최근 슬롯을 임의 초기화하거나 다른 슬롯으로 몰래 바꾸지 않습니다.

## 새 게임

**새 게임 → 슬롯 선택 → 선택 슬롯에 새 게임 시작**을 누릅니다. 빈 슬롯은 기존 신규 게임 흐름으로 들어갑니다. 사용 중인 슬롯은 기획사·날짜를 보여주는 두 번의 확인을 통과해야 교체합니다. 취소가 기본값입니다.

사진은 공통 사용자 폴더 `%LOCALAPPDATA%\IDOL_Manager\user_assets\idols`에 넣을 수 있습니다. 배포물에는 사용자의 아이돌 원본 사진·음악·세이브가 포함되지 않습니다. 최초 드래프트에는 서로 다른 사진 200명 이상이 필요합니다. 사진이 없으면 새 게임 생성은 안내와 함께 중단하고 기존 슬롯을 보존합니다.

최신 창단 준비 7일, 월요일 연습생 동시 신청, 기존 계약·선수단·경기·성장·재정 규칙을 그대로 사용합니다.

## 저장 위치

```
%LOCALAPPDATA%\IDOL_Manager\
  saves\slot1\game.sqlite3
               meta.json
               thumbnail.png
               identity.json
               config\
               backups\          # 해당 슬롯의 마이그레이션 백업
  saves\slot2\...                 # 완전히 별도의 DB
  saves\slot_backups\slot1\       # 교체·삭제 전 SQLite 백업
  saves\slot_backups\slot2\
  saves\.archives\                # 이전 슬롯 폴더 전체 보관
  config\slot_activity.json        # 확인된 저장/플레이 시각 및 측정 시간
  cache\slot1\, cache\slot2\       # 슬롯별 이미지 캐시
  user_assets\                    # 두 게임에서 읽는 공통 원본 사진·음악
```

게임 데이터의 원본은 SQLite입니다. JSON과 PNG는 표시용 보조 데이터이며 없어지거나 손상되면 정상 DB에서 다시 만듭니다. 썸네일·메타데이터 쓰기 실패가 이미 성공한 게임 저장을 취소하지 않습니다.

기존 게임처럼 각 작업은 현재 슬롯 DB에 자동 저장됩니다. 표시용 메타데이터는 커밋 감지 후 갱신하며, 썸네일은 대표 선수·로고·주차·순위 등 보이는 내용이 달라졌을 때만 다시 만듭니다. 플레이 시간은 이번 버전에서 실제 활성 게임 세션을 측정한 값이며 과거 시간을 추정하지 않습니다.

## 슬롯 전환과 종료

게임 안의 **메인 메뉴로 돌아가기**를 누르면 저장을 확인하고 기존 작업 스레드·조회·DB 모니터·UI를 정리한 뒤 시작 화면으로 돌아갑니다. 새 게임 창은 별도 서비스·DB·캐시를 사용합니다. 저장 확인 실패 시 **재시도/취소**로 현재 게임을 유지할 수 있습니다.

진행·관전 작업 중에는 완료 후 복귀/종료하도록 안내합니다. 한 번에 하나의 게임만 활성화되며 다른 프로세스가 실행 중인 슬롯은 삭제·교체·중복 실행할 수 없습니다. 비정상 종료 후 남은 미완료 SQLite 트랜잭션은 선택한 슬롯을 열 때 SQLite가 복구하며 다른 슬롯은 건드리지 않습니다.

## 삭제와 덮어쓰기

삭제와 새 게임 교체는 별도 버튼입니다. 두 작업 모두 두 단계 확인을 요구합니다. 삭제된 슬롯은 EMPTY로 바뀌며 다른 슬롯은 그대로 유지됩니다. 복구용 SQLite 백업과 이전 슬롯 폴더를 보관합니다. 자동으로 오래된 백업을 삭제하는 정책은 이번에 추가하지 않았습니다.

새 게임은 별도의 임시 폴더에서 생성·검증한 뒤 교체합니다. 교체 중 중단되면 복구 기록으로 이전 슬롯을 되돌릴 수 있습니다. DB가 열린 채로 이동·삭제하지 않도록 슬롯 잠금과 창 종료 절차를 사용합니다.

## 썸네일과 순위

400×225 PNG에 로고·선수 사진 두 장·기획사·시즌/구간/주차·순위를 합성합니다. 원본 사진은 변경하지 않습니다.

첫 선수는 현재 1군 리더 → 1군 CA 최고 → 소속 프로 CA 최고 → 전체 소속 CA 최고 순서입니다. 둘째는 첫 선수를 제외한 1군 CA 최고 → 프로 CA 최고 → 연습생 CA 최고 순서입니다. CA 동률은 안정적인 ID 순서로 선택합니다. CA는 기존 8개 능력치 평균이며 건강·PA를 포함하지 않습니다. 사진·로고가 없으면 플레이스홀더와 기획사명을 표시합니다.

득점 경기가 없는 시점의 순위는 미정입니다. 확정된 시즌 최종 순위가 있으면 이를 사용하고, 진행 중 승점 동률은 공동 순위로 표시합니다.

전체 검증·변경 파일·스크린샷은 `reports/start_menu/RESULTS.md`를 확인하세요.
