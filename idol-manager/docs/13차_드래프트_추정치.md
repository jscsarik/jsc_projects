# 13차 드래프트 추정치 · 구현 및 검증 보고

## 사용법

`실행하기.bat`를 실행하고 **최초 드래프트**를 엽니다. 기존 게임을 계속 사용하며 새 게임을 만들 필요가 없습니다. 완료된 드래프트는 다시 실행하지 않습니다.

후보 표는 사진·이름·나이·8개 현재 능력치 추정 범위·추정 종합·상태를 표시합니다. 이름 검색, 최소/최대 나이, 지명 가능/전체/지명 완료 필터와 숫자 기준 정렬을 지원합니다. 가로 스크롤로 모든 열을 확인합니다. 작은 창에서는 상세·기획사 순서 표도 스크롤합니다.

후보 선택 → **지명하기** → 확인 흐름은 동일합니다. 운영 기획사가 지명한 선수는 오른쪽 상세에서 실제 현재 능력치 8개와 실제 평균을 즉시 확인합니다. 지명 이력이나 지명 완료 필터에서도 다시 확인할 수 있습니다. 다른 기획사 선수는 이 드래프트 화면에서 추정 범위로 표시하며, 선수단 등 다른 기존 화면의 공개 정책은 변경하지 않았습니다. 잠재력은 지명 전후 모두 비공개입니다.

## 범위 생성과 저장

실제 현재 능력치 CA를 먼저 확정한 뒤 `max(0, CA-4)`부터 `min(CA,96)`까지의 가능한 정수 시작점 중 하나를 균등 추첨합니다. 공개 범위는 `[시작점, 시작점+4]`입니다. 항상 연속 정수 5개이며 실제 CA를 포함하고 0~100을 벗어나지 않습니다. 실제 값이 최솟값·중간값·최댓값 어느 위치에도 있을 수 있습니다. CA 0은 0~4, CA 100은 96~100입니다.

능력치마다 별도로 추첨하고 원래 능력치 생성과 독립적인 난수를 사용합니다. 실제 CA·PA·생성 유형을 변경하지 않습니다. 범위 생성은 PA·건강·특별 유망주 정보를 읽지 않습니다. **범위 상한은 잠재력 상한이 아닙니다.** 추정 종합은 공개된 8개 범위 중간값 평균을 소수 한 자리로 표시하며 실제 종합을 읽지 않습니다.

DB 버전은 **9**입니다. 추가 테이블 `draft_estimates`는 `(person_id,skill)` 키와 `low,high`를 저장합니다. 후보 200명 × 8개 = 1,600건입니다. 새로고침·재실행 시 저장값만 읽으며 UPDATE 방지 트리거로 공개 범위 덮어쓰기를 차단합니다. 명시적으로 새 게임을 생성할 때는 기존 새 게임 처리의 연쇄 삭제 규칙을 따릅니다.

이전 DB는 SQLite 백업 후 하나의 트랜잭션에서 스키마와 누락 범위만 추가합니다. 실패하면 모두 롤백합니다. 완료된 드래프트에도 표시용 범위만 보완하고 지명 결과를 다시 계산하지 않습니다. 과거 스카우팅 자료가 없는 기존 저장은 보완 시점의 현재 능력치로 범위를 생성합니다. 향후 성장이 추가되더라도 공개된 초기 범위를 자동 재추첨하지 않습니다.

## AI와 공개 정보 경계

`DraftSession.snapshot()`은 저장 범위와 공개 신원·지명 정보만 조회하며 실제 CA·PA를 읽지 않습니다. 기본 AI는 추정 종합이 높은 후보를 선택하고, 동률이면 가장 높은 개별 추정 중간값 → 낮은 나이 → 고유 ID 순으로 결정합니다. 별도 정책 모듈이며 DB에 접근하지 않습니다. 선수단 조합 최적화는 이번에 추가하지 않았습니다.

실제 저장은 플레이어와 AI 모두 기존 `DraftEngine.pick()`을 사용합니다. 10개 기획사·16라운드 스네이크·160명 지명·40명 미지명·턴 검증·중복 방지를 유지했습니다. 기존 저수준 `BlindCandidate` API는 호출자 호환용으로 유지하며 UI/기본 AI는 `DraftSession`의 추정 후보를 사용합니다.

지명 후 `revealed_player()`는 운영 기획사·저장된 지명·실제 소속을 확인한 다음 `abilities.skill,value`만 읽습니다. 미지명·타 기획사 선수는 실제 CA 조회 전에 차단합니다. PA는 이 경로에서도 읽지 않습니다. SQL 접근 차단 테스트로 생성 경로의 PA 미사용, 공개/AI 경로의 CA·PA 미조회, 소속 선수 조회의 PA 미조회를 검증했습니다.

## 원본 보호 및 백업

중단 전 원본은 버전 7·드래프트 0건·정규 결과 0건이었으며 다음 백업을 생성했습니다.

`data/backups/idol_manager_before_draft_estimates_development_20261027_195752_380344_KST.sqlite3`

재개 시 원본은 이미 버전 9·드래프트 160건·정규 경기 75건·absolute_day 21(revision 22) 상태였습니다. 이 진행 기록을 되돌리지 않았으며 다음 추가 백업을 생성했습니다.

`data/backups/idol_manager_before_estimates_continuation_20261027_214256_800018_KST.sqlite3`

재개 후 원본 DB를 읽기 전용으로 확인하고 복사본에서만 시험했습니다. 최신 원본 40개 테이블의 전체 행, 기존 사진·음악 등 assets 파일 462개, BGM 설정은 추가 백업 시점과 일치합니다. 무결성·외래키 검사도 통과했습니다. 중단 전과 재개 시점의 진행 기록 차이는 별도로 남겼으며 이전 상태로 덮어쓰지 않았습니다.

실제 구버전 복사본은 버전 7 → 9 확장 후 기존 32개 테이블 전체 행 보존과 신규 범위 1,600건의 유효성을 확인했습니다. 별도 완료 세이브 시험은 드래프트 160건·정규 결과·완료 특별전 3단계·피로/부상·리더·날짜·자금 등 모든 기존 테이블 행 보존 및 실패 시 전체 롤백을 확인했습니다.

검증 자료: `estimates_continuation_preservation.json`, `estimates_actual_copy_migration.json`, `estimates_windows_ui.json`.

## 제한

다른 기획사 지명 선수의 실제 CA는 드래프트 화면에서 공개하지 않습니다. AI는 공개 범위 순위 정책이며 조합 최적화는 구현하지 않았습니다. 실제 원본에서 지명이나 경기를 새로 생성하는 수동 시험은 데이터 보호를 위해 하지 않았습니다. PA 공개·코치·성장·포스트시즌·시즌 구조 변경·경기 연출 개선은 추가하지 않았습니다.
